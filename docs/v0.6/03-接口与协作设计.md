# 第三部分：接口与协作设计（V0.6）

[返回 V0.6 主文档](../V0.6-完整软件设计方案.md)

> 本文定义 V0.6 Go API、数据类型和上下游协作契约。上游只调用 TriggerInit 和 EventTriggerNotify；下游只提供 TryEnqueue(TaskInvocation)。

## 第 10 章 接口范围与公共类型

### 10.1 参与方

| 参与方 | 职责 | 与本模块的接口关系 |
|---|---|---|
| 上游 SMC Actor / Data Bucket SDK | 写入并 Commit 数据，提供数据地址和长度，维护 Session 生命周期 | 启动阶段调用 TriggerInit；运行阶段调用 EventTriggerNotify |
| Pheromone-mini（Go） | 配置加载、Registry、DIRECT、Event Trigger、Task Builder、Task Router、Delay Queue | 提供两个上游 API；调用下游 TryEnqueue |
| Task Coroutine Pool | 原子任务入队、队列消费、协程调度、SO / Function 加载和执行 | 只提供 TryEnqueue(TaskInvocation) |
| Function / Object SDK | 处理 TaskContext 输入，通过 Object API 写出数据 | 输出事件时注入当前 func_name |

### 10.2 接口方向

~~~mermaid
flowchart LR
    APP["上游应用启动流程"] -->|"TriggerInit(appJSONPath)"| PM["Pheromone-mini（Go）"]
    SDK["上游 Data Bucket SDK"] -->|"EventTriggerNotify(event, sourceFuncName, dataAddr, dataSize)"| PM
    PM -->|"TryEnqueue(TaskInvocation)"| POOL["Task Coroutine Pool"]
    POOL -->|"按 SOName + FuncName 加载并执行"| FN["Function"]
    FN -->|"Object API Commit；SDK 注入 sourceFuncName"| SDK
~~~

### 10.3 接口分组与边界

- A 组：本模块提供给上游的 API，共两个：TriggerInit、EventTriggerNotify。
- B 组：下游 Task Coroutine Pool 唯一接口：TryEnqueue(TaskInvocation)。
- 不存在 Pool 静态 Function 注册接口，不存在 register_function_configs。
- 不存在 DataRef Adapter、validate、retain、release 等 Data SDK 回调。
- FunctionInfo（so_name、func_name、resource）随 TaskInvocation 传递。
- Pool TryEnqueue 不带 ctx；Pool 实例自身持有队列和运行状态。

### 10.4 API 清单

#### 10.4.1 A 组：本模块提供给上游的 API

| API ID | API 名称 | 调用方 | 调用阶段 | 功能 |
|---|---|---|---|---|
| PM-API-005 | TriggerInit | 上游应用启动流程 | 启动阶段 | 传入 app.json 路径；模块读取 app.json 和其引用的 function.json，完成解析、校验及 Registry 初始化 |
| PM-API-004 | EventTriggerNotify | Data Bucket SDK / Object SDK | 每次数据 Commit 成功后 | 提交 Bucket、Key、Session、来源函数和数据地址，触发 DIRECT / Bucket Trigger 判断并路由任务 |

PM-API-004 保持既有编号；新增初始化 API 使用 PM-API-005。除以上两个 API 外，不暴露 Registry 生命周期、单独 JSON Parser 或索引操作接口。

#### 10.4.2 B 组：下游 Task Coroutine Pool API

| API 名称 | 调用方 | 功能 |
|---|---|---|
| TryEnqueue | Task Router | 原子检查队列容量并提交完整 TaskInvocation |

TryEnqueue 是下游唯一交互接口。不提供 register_function、unregister_function、wake_one 或 DataRef 操作。

### 10.5 公共类型与返回语义

#### 10.5.1 DataReadyEvent

~~~go
type DataReadyEvent struct {
    Bucket    string
    Key       string
    SessionID string
}
~~~

DataReadyEvent 仅包含 Bucket、Key、SessionID，不包含 sourceFuncName、dataAddr、dataSize、payload_type、DataRef、app_name、event_id、trigger_name 或目标函数。

#### 10.5.2 TaskArgument

~~~go
type TaskArgument struct {
    Key      string
    DataAddr unsafe.Pointer
    DataSize uint64
}
~~~

Key 必须存在；DataAddr 在 DataSize 大于 0 时必须非空。当前一次事件对应一个输入对象，Args 长度为 1。

#### 10.5.3 InputMode

~~~go
type InputMode uint8

const (
    InputValue InputMode = iota
    InputKeyValue
    InputKeyOnly
)
~~~

| 值 | 来源 | Function 输入语义 |
|---:|---|---|
| InputValue | trigger_option=0；DIRECT 固定此模式 | Value |
| InputKeyValue | trigger_option=1 | Key + Value |
| InputKeyOnly | trigger_option=2 | Key Only |

#### 10.5.4 ResourceSpec 与 FunctionInfo

~~~go
type ResourceSpec struct {
    CPUCores float64
    MemoryMB uint64
}

type FunctionInfo struct {
    SOName   string
    FuncName string
    Resource ResourceSpec
}
~~~

SOName 与 FuncName 作用不同。Resource 用于本模块 Task Router 准入判断，并随 TaskInvocation 一起传给 Pool。当前不定义 Execution 字段。

#### 10.5.5 TaskInvocation

~~~go
type TaskInvocation struct {
    SessionID string
    Function  FunctionInfo
    InputMode InputMode
    Args      []TaskArgument
}
~~~

TaskInvocation 不包含 AppName、Bucket、sourceFuncName、TriggerName、DataRef 或固定 handler 字段。

#### 10.5.6 EventTriggerNotify 错误语义

EventTriggerNotify 返回 Go error，不定义大型状态码枚举：

| 返回 | 语义 |
|---|---|
| nil | 通知处理流程正常完成；无 Trigger 命中也属于正常处理 |
| ErrNotInitialized | 模块尚未初始化 |
| ErrInvalidArgument | 输入参数非法 |
| ErrInternal | 不可恢复的内部错误 |

资源不足、无 Trigger 命中和 Pool 队列无容量是运行期路由结果，不扩展为公共 API 状态码。

#### 10.5.7 Pool 入队返回值

~~~go
type EnqueueResult uint8

const (
    EnqueueAccepted EnqueueResult = iota
    EnqueueNoCapacity
    EnqueueError
)
~~~

| 返回值 | 语义 | Router 行为 |
|---|---|---|
| EnqueueAccepted | Pool 已原子入队并接收任务描述符 | Router 释放自己的描述符副本 |
| EnqueueNoCapacity | Pool 当前队列无可接收容量，未接管任务 | 按 Delay Queue 配置暂存或终止 |
| EnqueueError | Pool 内部错误，未接管任务 | 终止任务并记录内部错误 |

### 10.6 A 组：本模块对上游 API 规格

#### 10.6.1 PM-API-005：TriggerInit

~~~go
func TriggerInit(appJSONPath string) error
~~~

职责：根据 app.json 文件路径加载 App 配置及其引用的 function.json，完成解析、校验、索引构建并发布内部 Registry。

路径和加载规则：

1. appJSONPath 不能为空；模块读取文件前转换为规范化绝对路径。
2. app.json 中 functions[].config_path 必须是相对路径。
3. function.json 路径相对于 app.json 所在目录解析。
4. function.json 路径不得通过 .. 路径穿越逃逸出配置根目录。
5. 一个 function.json 描述一个 Function；一个 app.json 可以引用多个 function.json。

初始化处理顺序：

1. 读取 app.json。
2. 解析 App 顶层配置和函数配置文件引用。
3. 逐个读取 function.json，解析 SOName、FuncName、Resource。
4. 校验 App、Function、Bucket、DIRECT、Trigger 和 Delay Queue 配置。
5. 校验 DIRECT / Trigger 引用的 func_name 均存在于当前 App。
6. 在临时对象中构建 Function、Bucket、DIRECT、Trigger 索引。
7. 全部成功后原子发布当前 AppRecord；任何一步失败，不留下部分可见配置。

每个 app.json 描述一个 App。单进程加载多个 App 时，可在业务事件开始前多次调用 TriggerInit；所有初始化调用完成后再开放业务事件。运行期开始后不再接受新配置。

#### 10.6.2 PM-API-004：EventTriggerNotify

~~~go
func EventTriggerNotify(
    event DataReadyEvent,
    sourceFuncName string,
    dataAddr unsafe.Pointer,
    dataSize uint64,
) error
~~~

入参：

| 参数 | 类型 | 必须 | 说明 |
|---|---|---:|---|
| event | DataReadyEvent | 是 | 仅 Bucket、Key、SessionID |
| sourceFuncName | string | 否 | 数据生产函数名称；外部 SMC Actor 传空字符串 |
| dataAddr | unsafe.Pointer | DataSize > 0 时必须 | 已 Commit 数据地址 |
| dataSize | uint64 | 是 | 数据长度；零长度数据允许 dataAddr 为空 |

处理顺序：

1. 校验 event、Bucket、Key、SessionID、dataAddr 和 dataSize。
2. 根据 Bucket 查询全局 Bucket Index，定位所属 App。
3. sourceFuncName 非空时，校验其属于该 App。
4. 查询 DIRECT Dependency Index。
5. 存在 DIRECT 目标时，为每个 target func_name 构建 DIRECT Task，InputMode 固定 InputValue；本次事件跳过 Bucket Trigger。
6. sourceFuncName 为空或不存在 DIRECT 目标时，查询 Bucket Trigger[]，逐条执行 Immediate / ByName 匹配。
7. 每条命中规则独立构建 TaskInvocation；当前 Args 长度为 1。
8. Task Router 根据 FunctionInfo.Resource 执行 CPU / Memory 预检查。
9. 资源不足不调用 TryEnqueue，进入资源不足 TODO 分支。
10. 资源满足时调用 TryEnqueue；NoCapacity 按 Delay Queue 规则处理。

EventTriggerNotify 返回 nil 表示通知处理流程正常完成，不承诺目标 Function 已经开始或完成执行。无 Trigger 命中也返回 nil。

### 10.7 B 组：下游 Task Coroutine Pool API 规格

#### 10.7.1 Pool 接口

~~~go
type TaskPool interface {
    TryEnqueue(task TaskInvocation) EnqueueResult
}
~~~

该接口不带 ctx 参数。Go 方法接收者 / Pool 实例自身持有队列、协程池和运行状态；不需要额外 ctx。

本模块在内部依赖装配时绑定下游 Pool 实现，不向上游提供 SetPool、RegisterPool 或其他第三个 API。

#### 10.7.2 TryEnqueue 调用语义

1. TryEnqueue 必须原子完成容量判断和入队。
2. Accepted 表示 Pool 已复制 TaskInvocation 的 Args 切片及其后续执行需要独立持有的描述符；Go string 可安全共享其不可变内容。
3. Pool 不复制、不释放 DataAddr 指向的业务数据。
4. NoCapacity 表示未接管任务；Pool 不得在返回后继续引用调用方可变 Args 切片。
5. Error 表示未接管任务。
6. Pool 成功接收后，必须保证任务最终能被内部消费者发现。
7. Pool 不要求本模块额外调用 wake_one。

#### 10.7.3 Pool 消费与唤醒责任

- Pool 负责队列消费者、协程创建、等待、唤醒和任务完成。
- Pool 根据 TaskInvocation.Function.SOName 和 FuncName 识别执行目标。
- Pool 按自己的实现选择 Function 加载和符号定位机制；本模块不规定 Go Plugin、cgo 或 native SO Loader。
- Pool 不负责释放 DataAddr 指向的上游数据内存。

### 10.8 Function 执行上下文契约

#### 10.8.1 逻辑 TaskContext

~~~go
type TaskContext struct {
    SessionID string
    SOName    string
    FuncName  string
    InputMode InputMode
    Args      []TaskArgument
}
~~~

TaskContext 是 Pool 与 Function / Object SDK 的逻辑执行上下文，不是本模块第三个上游 API。具体函数加载和调用 ABI 由下游 Pool 决定。

#### 10.8.2 Object API 与来源函数注入

Function 通过 Object API 写入输出数据。Object SDK 从当前 TaskContext.FuncName 取得当前正在执行的函数名称，作为独立参数 sourceFuncName 传入 EventTriggerNotify。外部 SMC Actor 不属于已注册 Function，传空字符串。

## 第 11 章 上下游协作流程与生命周期

### 11.1 启动期

~~~go
if err := TriggerInit("./config/app.json"); err != nil {
    return err
}
~~~

模块内部读取 app.json，并按 config_path 加载 function.json。上游不负责解析 JSON，也不负责调用 Registry 注册接口。

### 11.2 运行期：上游通知一次 Commit

~~~go
event := DataReadyEvent{
    Bucket:    "b_input",
    Key:       "image_001",
    SessionID: "session_1001",
}

err := EventTriggerNotify(
    event,
    "",
    committedObjectAddr,
    committedObjectSize,
)
~~~

Function 输出对象时，第二个参数传入当前 TaskContext.FuncName；外部 Actor 传空字符串。

### 11.3 运行期：Pool 接收任务

~~~text
TaskInvocation
    SessionID = session_1001
    Function.SOName = image_process.so
    Function.FuncName = crop_image
    Function.Resource = {CPUCores: 2, MemoryMB: 512}
    InputMode = InputValue
    Args[0]:
        Key = image_001
        DataAddr = committedObjectAddr
        DataSize = committedObjectSize
~~~

Task Router 先检查资源，再调用 TryEnqueue。Pool 自行根据 SOName + FuncName 加载并执行目标函数。

### 11.4 端到端时序

~~~mermaid
sequenceDiagram
    participant App as Application Bootstrap
    participant SDK as Data Bucket SDK
    participant ET as Event Trigger
    participant TB as Task Builder
    participant RT as Task Router
    participant Pool as Task Coroutine Pool
    participant Fn as Function

    App->>ET: TriggerInit(appJSONPath)
    ET->>ET: 读取 app.json / function.json，构建 Registry
    SDK->>ET: EventTriggerNotify(event, sourceFuncName, dataAddr, dataSize)
    ET->>ET: Bucket 定位 / DIRECT 判断 / Trigger 匹配
    ET->>TB: TaskAction + EventDataView
    TB->>TB: 构建 TaskInvocation.Args[]
    TB->>RT: TaskInvocation
    RT->>RT: 查询当前可用 CPU / Memory
    alt 资源不足
        RT->>RT: RESOURCE_INSUFFICIENT TODO；不调用 Pool
    else 资源满足
        RT->>Pool: TryEnqueue(TaskInvocation)
        alt Accepted
            Pool->>Pool: 入队并由内部协程消费
            Pool->>Fn: 根据 SOName + FuncName 加载并执行
        else NoCapacity
            RT->>RT: Delay Queue 或终止
        else Error
            RT->>RT: 记录内部错误并终止
        end
    end
~~~

### 11.5 内存所有权与生命周期契约

| 对象 | 创建方 | 使用方 | 释放方 / 有效期 |
|---|---|---|---|
| DataReadyEvent | 上游 SDK | EventTriggerNotify | 上游保证 notify 调用期间有效 |
| sourceFuncName | 上游 SDK / TaskContext | DIRECT 匹配 | 上游保证 notify 调用期间有效 |
| Key / SessionID 字符串 | 上游 SDK | Task Builder / Pool / Function | Task Builder 复制异步任务所需字符串 |
| TaskInvocation / Args 描述符 | Task Builder | Router / Pool | Router 或 Pool 管理自己的描述符副本 |
| DataAddr 指向的数据 | 上游 Data SDK | Task Builder / Pool / Function | 上游在 Session 结束且所有相关任务终态后回收 |

不可违反的规则：

1. DataAddr 是借用地址，不发生所有权转移。
2. Scheduler 和 Pool 不得释放 DataAddr。
3. Task Builder 不复制数据内容，只构建参数描述符。
4. 一个事件命中多个 Task 时，所有 Task 都可能访问同一 DataAddr。
5. 上游必须将 Delay Queue 中的待提交任务也视为未完成任务。
6. Session 数据回收必须发生在该 Session 所有相关任务完成或终止之后。
7. DataAddr 应指向上游管理的共享内存 / mmap 区域，不应指向未固定的 Go Heap 对象。

### 11.6 并发、重入与调用顺序

- TriggerInit 仅在启动阶段调用；所有配置初始化完成后再开始业务事件。
- Registry 发布后只读。
- EventTriggerNotify 可被多个上游线程并发调用。
- Task Builder 不得把调用方的临时字符串引用直接放入异步队列。
- Task Router 和 Delay Queue 必须线程安全。
- TryEnqueue 必须原子完成队列准入和入队。
- 同一数据地址被多个任务共享时，上游负责保证并发读期间地址稳定。
- 模块关闭前停止接收新通知，等待在途通知和 Router PendingTask 进入终态；Pool 已接收任务按 Pool 的关闭契约完成或终止。

### 11.7 上下游责任边界与联调验收

#### 11.7.1 本模块负责

- TriggerInit(appJSONPath)：读取 app.json 及其引用的 function.json，完成解析、校验和 Registry 初始化。
- EventTriggerNotify：最小事件、来源函数和数据地址通知。
- Function / Bucket / DIRECT / Trigger 索引。
- Task Builder.Args[]。
- CPU / Memory 资源预检查。
- TryEnqueue 调用与 Delay Queue。

#### 11.7.2 上游 Data Bucket SDK 负责

- Commit 成功后调用 EventTriggerNotify。
- 传递 Bucket、Key、SessionID、sourceFuncName、dataAddr、dataSize。
- 保证数据地址在 Session 相关任务完成或终止前有效。
- Session 结束后回收数据。
- Function 输出对象时注入当前 FuncName。

#### 11.7.3 下游 Task Coroutine Pool 负责

- 运行期提供唯一 TryEnqueue(task TaskInvocation)。
- 不要求 ctx 参数或静态 Function 注册。
- 原子入队、队列消费和协程唤醒。
- 根据 SOName + FuncName 加载并执行 Function。
- 复制任务描述符和 Args 切片，不复制、不释放上游数据内容。

#### 11.7.4 联调验收清单

- 上游只使用 TriggerInit 和 EventTriggerNotify 两个 API。
- TriggerInit 只接收 app.json 路径，并加载其引用的 function.json。
- DataReadyEvent 只有 Bucket、Key、SessionID。
- sourceFuncName 是独立参数，外部 Actor 使用空字符串。
- dataAddr / dataSize 与上游 Commit 对象一致。
- 不存在 DataRef Adapter 或 DataRef 相关 API。
- func_name 在当前 App 内唯一，DIRECT 仅按 func_name 匹配。
- TaskInvocation 携带 FunctionInfo 和 Args[]，当前 Args 长度为 1。
- 下游 Pool 只有 TryEnqueue，不带 ctx。
- 不存在 Pool 静态 Function 注册 API。
- Task Router 在 TryEnqueue 前执行 CPU / Memory 资源预检查。
- 资源不足不调用 TryEnqueue，走 TODO 分支。
- Pool NoCapacity 与资源不足分开处理。
- Session 生命周期覆盖所有派生任务。
