# Pheromone-mini V0.6 完整软件设计方案

**版本：** V0.6  
**日期：** 2026-11-26  
**状态：** 预研 Demo 设计基线  
**实现语言：** C11  
**前序版本：** V0.5

## 1. V0.6 核心结论

V0.6 在 V0.5 的单节点、单进程调度范围内恢复 Pheromone 的 DIRECT 独立依赖路径，并重构 DataReadyEvent、下游 Task Invocation 和 Task Router 资源准入设计。V0.6 不实现 Rerun。

本模块负责业务流程③④⑤：接收 DataReadyEvent，判断 DIRECT 或 Bucket Trigger 路径，匹配规则，构建最小 TaskInvocation，并通过 Task Router 向下游 Task Coroutine Pool 原子提交。

## 2. 冻结设计基线

| 维度 | V0.6 冻结规则 |
|---|---|
| 配置文件 | 仅一份 app.json |
| App 注册 | 上游传入完整 JSON，由本模块 register_app 统一解析、校验和发布 |
| App 名称 | app_name 是 App Registry 全局唯一注册 KEY，不进入 DataReadyEvent |
| Bucket | 在当前 App Registry 的全部 App 范围内全局唯一 |
| Function | 每个 SO 对应一个无状态 handler；入口固定为 handler |
| SO 部署 | 每节点固定放在 /dev/shm，由下游框架加载 |
| 依赖 | DIRECT 是独立依赖路径；配置在 app.json dependencies |
| Trigger | 仅 Immediate、ByName 两种 Bucket Trigger |
| 多 Trigger | 一个 Bucket 可关联多条 Trigger；逐条匹配，逐条生成 Task |
| DIRECT 优先级 | source_function 存在 DIRECT 依赖时走 DIRECT 路径，不再对本次事件执行 Bucket Trigger 匹配；否则进入 Bucket Trigger 路径 |
| DataReadyEvent | bucket、key、session_id、payload_type、data_size、载体数据；source_function 在函数输出时提供，外部 Actor 写入可为空 |
| 数据载体 | INLINE / SHARED_MEMORY，由 Data SDK 选择；本模块不判断 1KB 阈值 |
| Task 输入 | so_name、session_id、input_mode、可选 key、payload_type、data_size、payload |
| 下游注册 | Function 静态 resource / execution 元数据在注册阶段一次性提供给 Pool |
| 本地准入 | Task Router 调用原子 task_pool_try_enqueue；Pool 接口完成容量检查和入队 |
| 协程调度 | Pool 内部负责队列消费和协程唤醒；本模块不调用 wake_one |
| 延时调度 | app.json 全局 Delay Queue：enabled、retry_interval_ms、max_wait_ms |
| 队列无容量 | Delay Queue 开启则暂存并重试；关闭或超时则记录日志并释放资源 |
| 执行超时 / Rerun | 不实现；不定义 resource.timeout_ms |
| 研发范围 | 单节点、单进程；不实现进程间、节点间分发 |

## 3. 核心模块

1. **App Registry**：加载单一 app.json，维护 App、全局 Function、Bucket、DIRECT Dependency 和 Trigger 索引。
2. **DIRECT Dependency**：根据 source_function 查找目标函数，独立生成 DIRECT Task。
3. **Event Trigger**：按 Bucket 查找 Trigger[]，执行 Immediate / ByName 匹配。
4. **Task Builder**：把 DIRECT 或 Trigger 命中结果转换为最小 TaskInvocation，处理 Inline 复制和 DataRef retain。
5. **Task Router**：原子入队、全局 Delay Queue、无本地容量时的日志与远程调度扩展预留。

## 4. 总体执行路径

~~~mermaid
flowchart TD
    A["SMC Actor / Function handler"] --> B["Data Bucket SDK 写入并 Commit"]
    B --> C["DataReadyEvent：bucket / key / session / payload"]
    C --> D["App Registry：全局 Bucket 索引"]
    D --> E{"source_function 有 DIRECT 依赖？"}
    E -->|是| F["DIRECT Dependency"]
    E -->|否| G["Event Trigger：Immediate / ByName"]
    F --> H["Task Builder"]
    G --> H
    H --> I["Task Router"]
    I --> J{"task_pool_try_enqueue"}
    J -->|ACCEPTED| K["Task Coroutine Pool"]
    J -->|NO_CAPACITY| L{"全局 Delay Queue 启用？"}
    L -->|是| M["Delay Queue：到期重新提交"]
    M --> I
    L -->|否| N["记录 PROCESS_DISPATCH_REQUIRED"]
    K --> O["Pool 内部队列消费 / 协程调度"]
    O --> P["/dev/shm/<so_name> / handler"]
~~~

DIRECT 和 Bucket Trigger 是两条独立路径，不把 DIRECT 伪装成第三种 Trigger Primitive。DIRECT 命中时优先走 DIRECT；没有 DIRECT 依赖时才执行 Bucket Trigger 匹配。

## 5. 上下游接口

### 5.1 提供给上游 Data Bucket SDK

- register_app：注册完整 app.json。
- event_trigger_notify：接收一次成功 Commit 对应的 DataReadyEvent。
- DataReadyEvent 不含 app_name、trigger_name、primitive_type、target_function、event_id、active_trigger_names、IP 地址或 RPC 地址。
- bucket 全局唯一；本模块根据 bucket 反查 App。
- source_function 仅用于 DIRECT 路径：由 Function handler 写对象时 SDK 从 TaskContext 注入；外部 Actor 写入可为空。
- DataRef 由 SDK 定义为不透明引用，提供 validate / retain / release。

### 5.2 对下游 Task Coroutine Pool 的要求

静态注册阶段调用 task_pool_register_function，传递 so_name 和函数级 resource / execution 配置。每次任务仅传递最小 TaskInvocation。

TaskInvocation 不包含 app_name、bucket、event_id、task_id、source_function、trigger_name、source_type、resource、execution 或 handler 名称。handler 固定为 handler；SO 名称用于下游定位 /dev/shm/<so_name>。

Pool 提供原子 task_pool_try_enqueue。ACCEPTED 时复制 Inline 数据并接管 DataRef；拒绝时不得保留 Task 或 DataRef。Pool 自行消费队列并管理协程，不向本模块要求单独唤醒接口。

## 6. 关键数据与生命周期

- Inline 数据在 notify 调用期间由 SDK 借用；Task Builder 为每个需要 Value 的 Task 复制。
- Shared-Memory DataRef 在 Task Builder 中每个 Task 独立 retain。
- Task Router 在等待 Delay Queue 期间持有 Task 与 DataRef。
- Pool 返回 ACCEPTED 后，Pool 接管 Task 和对应 DataRef。
- NO_CAPACITY 不转移所有权；超时或终止失败由 Router 释放。
- KEY_ONLY 不复制 Inline 数据、不 retain DataRef。
- DataRef 必须绑定本次 Commit 的不可变版本；覆盖写不得改变已 retain 引用所指向的数据。

## 7. 本期明确不实现

- Rerun、自动重新执行、执行超时和 resource.timeout_ms。
- wake_one 或任何由本模块发起的协程唤醒操作。
- BySet、ByBatchSize、ByTime、DynamicGroup、Redundant 等其他 Trigger Primitive。
- Node Scheduler、Process Scheduler、Warm / Cold Executor、跨进程和跨节点分发。
- Data Bucket 创建/销毁、共享内存池、对象索引、数据复制/传输和 1KB 阈值判断。
- Task Coroutine Pool、TaskQueue、工作协程、SO Loader 和 handler 执行实现。
- 动态 Trigger 更新、Exactly-once、事件持久化和本期之外的事件去重。

## 8. V0.5 → V0.6 变更摘要

| 变更 | V0.6 处理 |
|---|---|
| DIRECT Dependency | 恢复为 P0 独立路径 |
| DataReadyEvent | 删除 app_name 和不必要调度字段；Bucket 全局唯一 |
| 下游 TaskDescriptor | 精简为 TaskInvocation；静态函数元数据单独注册 |
| 资源准入 | 原子 try_enqueue |
| 协程唤醒 | 删除单独 wake_one 调用 |
| 延时调度 | 增加全局 Delay Queue |
| Rerun | 不实现 |
| resource.timeout_ms | 删除 |
| 文档 | 新增 docs/v0.6，保留 docs/v0.5 |
