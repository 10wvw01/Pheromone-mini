## 第 20 章 测试与验收方案

### 20.1 测试分层

1. **本模块单元测试**：App Registry、Trigger 匹配、Task Builder、Task Router，使用 Mock Data SDK / Mock Pool。
2. **上游 Data SDK 契约测试**：确认 Commit-before-notify、Inline 生命周期、DataRef 版本与 retain/release、覆盖写语义。
3. **下游 Pool 契约测试**：确认 try_enqueue 原子性、描述符复制、引用接管、wake_one 与 Task 结束释放。
4. **端到端联调**：真实 SDK + 本模块 + 真实 Pool，在单节点单进程完成业务链路。

Mock Pool 仅是测试替身，不代表本模块实现协程池。所有用例记录输入配置、event_id、trigger_name、Task 数、入队结果、引用计数和关键日志。

### 20.2 核心测试用例

| 用例 | 输入 / 操作 | 预期 |
|---|---|---|

### 20.3 T09 / T10 的责任边界

T09 和 T10 是本模块必须通过的**数据载体接口契约测试**，不是本模块实现传输机制的任务。

| 项目 | T09 Inline | T10 Shared-Memory |
|---|---|---|
| 载体选择 | Data SDK 决定 | Data SDK 决定 |
| 传输实现 | 上游消息传输 | 上游共享内存 |
| 本模块接收 | inline_data + data_size | data_ref + data_size |
| Task Builder | 复制字节到 TaskDescriptor | retain 并原样传 DataRef |
| Task Pool | 使用队列中的字节副本 | map DataRef 读取，结束后 release |
| 本模块不做 | 不实现消息传输、不判断阈值 | 不分配共享内存、不复制大 Payload |

1KB 的精确边界、边界值归属和 SDK 内部传输性能由 Data SDK 团队测试。我们的 T09/T10 只验证载体字段、生命周期、Task 组装和向下游传递正确。

### 20.4 准入条件

- App Registry、Immediate/ByName、同 Bucket 多 Trigger、Task Builder、Task Router 的全部 P0 单测通过。
- T09/T10 真实数据载体契约测试通过。
- DataRef 对应版本在 Task 生命周期内有效，覆盖写不会使已入队任务读取错误版本。
- Pool 的入队、唤醒和引用接管契约通过。
- 队列满只记录日志，没有实际进程间分发。
- 无 Inline 悬空指针、DataRef 泄漏、重复 release、任务串线或部分成功被误报。
- 未完成真实 SDK / Pool 联调时，只能标记 Mock 验证完成，不得标记端到端验收通过。
