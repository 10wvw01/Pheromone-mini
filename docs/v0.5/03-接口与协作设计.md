# 第三部分：接口与协作设计（第 11～14 章）

[返回 V0.5 主文档](../V0.5-完整软件设计方案.md) · [C ABI 草案](appendix/C-C接口与Task-ABI.md)

## 第 11 章 公共数据结构与接口协议

### 11.1 接口分层

上游只需要两类交互：

- 注册配置：`register_app(registry, app_json, length)`，由 App Registry 统一管理。
- 通知数据：`event_trigger_notify(registry, event, result)`，由 Data SDK 在对象 Commit 成功后调用。

上游不直接调用 Function Index、Trigger Index、Task Builder 或 Task Router。下游通过 Pool Adapter 提供队列入队和唤醒接口。

### 11.2 DataReadyEvent

| 字段 | 含义 |
|---|---|
| event_id | SDK 生成的非零事件 ID |
| app_name | 已注册 App 的全局唯一 KEY |
| bucket / key / session_id | 对象逻辑身份和业务上下文 |
| source_function | 可选来源函数名，仅用于追踪，不参与路由 |
| payload_type | INLINE 或 SHARED_MEMORY，必须由 SDK 显式给出 |
| data_size | 本次提交对象的真实字节数 |
| inline_data / inline_size | INLINE 时随事件携带的数据及长度 |
| data_ref | SHARED_MEMORY 时的 DataRef，指向本次提交的数据版本 |

不再包含 tgt_function、DIRECT 目标或依赖边字段。事件只代表一次成功提交并由 SDK 显式通知的对象到达；覆盖写但未通知不产生事件。

### 11.3 TaskDescriptor

TaskDescriptor 至少包含：

- 身份：task_id、event_id、app_name、session_id。
- 执行目标：function_name、so_name、entry_name=handler、function_version。
- 规则来源：source_type（IMMEDIATE / BY_NAME）、trigger_name。
- 资源元信息：resource、execution。
- 输入元信息：bucket、key、input_mode、payload_type、data_size。
- 输入载体：Inline 字节副本，或 DataRef；KEY_ONLY 不带 Payload。

TaskDescriptor 不保存 Event 指针、Registry 指针、调用栈指针或原始 JSON 指针。SO 路径不由配置传入，固定由下游框架解析。

### 11.4 输入模式与 Payload 类型是两个维度

`input_mode` 表示函数希望收到哪些业务输入；`payload_type` 表示 SDK 如何传递数据，两者不能混为一谈。

| input_mode | INLINE | SHARED_MEMORY |
|---|---|---|
| INPUT_VALUE | value 字节副本 | DataRef |
| INPUT_KEY_VALUE | key + value 字节副本 | key + DataRef |
| INPUT_KEY_ONLY | 仅 key | 仅 key |

如果同一个 Bucket 的不同 Trigger 配置了不同 input_mode，则同一事件可以分别构建不同输入形态的 Task。

### 11.5 结果结构与错误语义

一次事件可能命中 0 到 N 条规则。结果至少包含 matched、enqueued、overflow、failed 计数，以及每条命中规则的 trigger_name、target_function、task_id、build_status、route_status 和 wake_status。

- 零匹配是正常成功。
- `enqueued` 只统计 try_enqueue 已接受的 Task；wake_one 是否找到等待协程不改变该计数。
- `overflow` 只统计队列满且未接收的 Task。
- `failed` 统计构建失败和其他 Pool 拒绝。
- 结果缓冲区不足必须在任何 Task 入队前检测，返回所需容量且无投递副作用。
- 部分成功不回滚；上游不得无差别重放整条事件。

## 第 12 章 上游协作接口 — Data Bucket SDK

### 12.1 Data SDK 负责什么

Data Bucket SDK 负责 Object 创建、容量校验、写入、Commit、共享内存管理、1KB 数据传输策略、DataRef 创建和底层消息/事件传输。本模块不实现这些能力。

Data SDK 必须在写入成功且数据对消费者可见后调用 event_trigger_notify。SDK 若已有事件队列，可由它消费事件后调用相同接口；本模块不要求新建事件队列。

### 12.2 Payload 传输契约

DataReadyEvent 使用显式 payload_type：

| payload_type | SDK 行为 | Scheduler 接收方式 |
|---|---|---|
| INLINE | 小数据随消息携带 | Task Builder 在 notify 期间复制字节 |
| SHARED_MEMORY | 大数据写入共享内存并提供 DataRef | Task Builder retain DataRef 并原样传递 |

1KB 是 SDK 的传输策略边界。Scheduler 不根据 data_size 再做一次阈值判断；它只校验 payload_type 与字段形态一致。1KB 究竟按 1000 还是 1024 字节解释，以及边界值归入哪种载体，由 Data SDK 团队在接口契约中冻结。

### 12.3 Commit-before-notify 与 Inline 生命周期

1. SDK 创建/定位 Object，校验写入长度不超过 Object 容量。
2. SDK 写入数据并 Commit，确保消费者可见。
3. SDK 构造 DataReadyEvent，填入 app/bucket/key/session/event_id/payload_type/data_size。
4. INLINE：事件缓冲区在 notify 返回前保持有效；Task Builder 在返回前将需要的 Payload 复制到每个 Task。
5. SHARED_MEMORY：SDK 持有基础引用；Task Builder 对每个需要 value 的 Task 单独 retain。
6. SDK 根据约定在 notify 返回后释放本次事件的基础引用。

SDK 不能在 notify 期间修改或释放 Inline 缓冲区。Inline 数据长度必须与 data_size 一致，并且不能超过接口约定的最大内联容量。

### 12.4 Shared-Memory DataRef 生命周期与覆盖写

DataRef 必须是可验证的不透明引用，且指向本次 Commit 的不可变对象版本。对每个 Task 的 retain 成功后，SDK 必须保证该版本在对应 release 前不会被回收或被其他数据覆盖。

团队已知约束：同一 Bucket/Key 多次 send_object 可能覆盖当前对象内容，但覆盖本身不会产生变更通知。因此：

- Scheduler 只处理显式 DataReadyEvent，不监听 Key 变化、不轮询 Bucket、不推断覆盖事件。
- 未产生新 DataReadyEvent 的覆盖写不会触发新的 Task。
- 已经生成 Task 的 DataRef 不能在执行时退化为“按 Bucket/Key 重新取最新对象”；必须仍指向该 Task 对应的提交版本。
- 若底层采用固定槽覆盖，Data SDK 需通过版本化引用、Copy-on-Write、引用保护或等价机制保证旧引用稳定；若无法保证，必须在联调前明确限制写入/消费并发语义。

### 12.5 DataRef Adapter

| 回调 | 语义 | 适用范围 |
|---|---|---|
| validate | 校验 DataRef、版本和 data_size；不增加引用 | SHARED_MEMORY |
| retain | 增加一份独立引用；失败不得增加 | SHARED_MEMORY 且目标需要 value |
| release | 释放此前成功 retain 的一份引用 | SHARED_MEMORY |
| map / unmap | 下游执行时映射/解除映射 | 下游 Data SDK Adapter |

Inline 不调用 retain/release；Task Builder 负责复制。KEY_ONLY 不调用 retain/release。DataRef 不得使用跨线程不安全的裸指针替代。

### 12.6 Object API 与 APP 约束

业务 SO 只能通过 Object/Data SDK API 读写 Bucket 对象，不得自行通过文件 I/O、网络 Socket 或其他旁路交换业务数据。APP 不得越过 Object 容量限制写入；容量检查与写入失败由 SDK 返回。Scheduler 不提供文件、Socket 或共享内存裸地址 API。

### 12.7 结果反馈

写入失败不得通知 Event Trigger。写入成功但任务未被队列接收时，SDK 必须区分“Object Commit 成功”和“Task 调度未全部接收”。检查逐项结果；部分成功不应盲目重放整条事件。队列满本期无自动跨进程转发、无自动重试。

## 第 13 章 下游协作接口 — Task Coroutine Pool

### 13.1 下游团队职责

下游团队负责 Task Coroutine Pool 的全部内部实现：

- TaskQueue 的容量、并发安全和存储。
- Task Coroutine 的创建、等待、唤醒和退出。
- SO 从 /dev/shm 加载、handler 符号解析和 ABI 校验。
- Inline Payload 的读取，以及 Shared-Memory DataRef 的 map/unmap。
- handler 调用、执行状态、异常处理和最终资源释放。

本模块不实现或维护 TaskQueue，不创建协程，不执行 dlopen/dlsym。

### 13.2 最小 Adapter 契约

~~~c
pool_enqueue_result_t (*try_enqueue)(
    void *pool_ctx, const task_desc_t *task);
pool_wake_result_t (*wake_one)(void *pool_ctx);
~~~

try_enqueue 必须原子完成容量检查与入队，并在返回前复制完整 TaskDescriptor。成功表示已接收并接管本 Task 的 DataRef；拒绝表示没有入队、没有保存描述符且没有接管引用。

成功入队后，Task Router 调用 wake_one。无等待协程时返回 WAKE_NO_WAITER，Task 仍留在队列；不能因为当前没有空闲协程就撤销入队。Pool 必须自行避免入队与协程转入睡眠之间的丢唤醒。

### 13.3 入队结果与所有权

| try_enqueue 结果 | 是否入队 | DataRef 所有者 |
|---|---:|---|
| ENQUEUE_OK | 是 | Pool |
| ENQUEUE_QUEUE_FULL | 否 | Router 负责 release |
| ENQUEUE_NOT_READY | 否 | Router 负责 release |
| ENQUEUE_RESOURCE_UNAVAILABLE | 否 | Router 负责 release |
| ENQUEUE_INVALID_TASK | 否 | Router 负责 release |
| ENQUEUE_INTERNAL_ERROR | 否 | Router 负责 release |

Inline Payload 已在 TaskDescriptor 中独立复制，Pool 成功入队后复制/保存完整描述符即可；没有 DataRef 需要释放。Shared-Memory 每个 Task 的 DataRef 由 Pool 在执行完成、失败或取消清理时释放。

### 13.4 唤醒语义

wake_one 只表达“尝试唤醒一个等待协程”，不是第二次入队。WAKE_SIGNALED 和 WAKE_NO_WAITER 都不改变已入队事实。若出现 WAKE_ERROR，Router 记录告警但不能把 Task 改为未接收或释放已接管引用；下游必须保证队列可被后续协程消费。

### 13.5 SO 加载与 handler 执行

Pool 从 `/dev/shm/<so_name>` 加载 SO，查找固定符号 `handler`。根据 input_mode 构造 TaskContext：

| 模式 | key | value |
|---|---|---|
| INPUT_VALUE | 不提供 | 只读数据视图 |
| INPUT_KEY_VALUE | 提供 | 只读数据视图 |
| INPUT_KEY_ONLY | 提供 | 不提供 |

Inline Payload 从 TaskDescriptor 副本读取；Shared-Memory 通过 DataRef 映射读取。handler 返回后解除映射、释放 DataRef 和任务描述符。Task 执行状态及完成通知由 Pool 管理，本模块不维护执行状态表。

## 第 14 章 关键业务时序

### 14.1 注册与启动

~~~mermaid
sequenceDiagram
    participant U as 上游
    participant SDK as Data Bucket SDK
    participant P as Task Coroutine Pool
    participant AR as App Registry
    U->>SDK: 初始化 Object 服务
    U->>P: 初始化任务协程池
    U->>AR: create registry + adapters
    U->>AR: register_app(app.json)
    AR->>AR: parse / validate / build indexes
    AR-->>U: 注册成功
    U->>AR: seal registry
    U->>SDK: 启用数据通知
~~~

### 14.2 小数据 Inline 路径（T09）

~~~mermaid
sequenceDiagram
    participant A as SMC Actor
    participant D as Data SDK
    participant E as Event Trigger
    participant B as Task Builder
    participant R as Task Router
    participant P as Task Pool
    A->>D: send_object(bucket,key,small_data)
    D->>D: Commit + 生成 INLINE 事件
    D->>E: event_trigger_notify(event)
    E->>B: 命中 Immediate / ByName
    B->>B: 复制 Inline Payload 到 TaskDescriptor
    B->>R: TaskDescriptor
    R->>P: try_enqueue
    P-->>R: ENQUEUE_OK
    R->>P: wake_one
    P-->>D: notify 结果
~~~

### 14.3 大数据 Shared-Memory 路径（T10）

~~~mermaid
sequenceDiagram
    participant A as SMC Actor
    participant D as Data SDK
    participant E as Event Trigger
    participant B as Task Builder
    participant R as Task Router
    participant P as Task Pool
    A->>D: send_object(bucket,key,large_data)
    D->>D: Commit + 生成 DataRef
    D->>E: event_trigger_notify(event)
    E->>B: 命中规则
    B->>D: validate + retain(DataRef)
    B->>R: 携带原 DataRef 的 TaskDescriptor
    R->>P: try_enqueue
    P-->>R: ENQUEUE_OK / 接管引用
    R->>P: wake_one
    P-->>D: notify 结果
    P->>P: 执行后 release(DataRef)
~~~

### 14.4 一个 Bucket 关联多个 Trigger

~~~mermaid
flowchart TD
    E["b_shared / key=input 的 DataReadyEvent"] --> R["Trigger Index: b_shared"]
    R --> A["Immediate → processor.so"]
    R --> B["ByName(input) → audit.so"]
    A --> T1["Task 1"]
    B --> T2["Task 2"]
    T1 --> Q["Task Router"]
    T2 --> Q
~~~

两条规则独立构建和入队。若两条规则目标相同，也仍然是两个独立 Task。

### 14.5 队列满

~~~mermaid
sequenceDiagram
    participant B as Task Builder
    participant R as Task Router
    participant P as Task Pool
    B->>R: 已构建 Task
    R->>P: try_enqueue
    P-->>R: ENQUEUE_QUEUE_FULL
    R->>R: release 本 Task 的 DataRef
    R->>R: 记录 PROCESS_DISPATCH_REQUIRED
    R-->>B: ROUTE_QUEUE_FULL / 未接收
~~~

不发生跨进程发送，不缓存等待重试。

### 14.6 同 Key 覆盖但没有通知

~~~mermaid
sequenceDiagram
    participant D as Data SDK
    participant E as Event Trigger
    D->>D: 第一次 send_object + Commit
    D->>E: DataReadyEvent #1
    E->>E: 匹配并生成 Task #1
    D->>D: 再次覆盖相同 Bucket/Key
    Note over D,E: 若无新 DataReadyEvent，不产生第二次匹配
~~~

Task #1 必须通过其 DataRef 读取第一次提交的数据版本，不能因 Key 当前值变化而读取到覆盖后的新数据。
