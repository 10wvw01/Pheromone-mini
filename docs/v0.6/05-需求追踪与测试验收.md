### 17.2 验收原则

1. 单元测试覆盖 app.json 解析、索引、DIRECT、Immediate、ByName、Task Builder 和 Task Router。
2. 参数测试覆盖 Key 必填、DataAddr / DataSize 一致性、Args 长度和 FunctionInfo。
3. 并发测试覆盖并发通知、共享数据地址、多目标任务、原子入队和 Delay Queue。
4. 资源测试覆盖 CPU / Memory 充足、不足和 cgroup 不可用兜底。
5. 上下游联调覆盖真实 Data SDK Commit 通知、真实 Pool TryEnqueue 和 FunctionInfo 透传。
6. 不执行 DataRef 引用计数、Inline 复制、Shared-Memory retain 等已删除设计的测试。
7. 测试代码使用 Go；不保留 C11 / C ABI 示例作为 V0.6 实现契约。

## 第 18 章 测试与验收方案

### 18.1 测试分层

- 配置单元测试：app.json 语法、字段类型、必填项、Function 唯一性、Bucket 唯一性和引用关系。
- 索引单元测试：func_name 索引、DIRECT 索引、Bucket Trigger 索引。
- Trigger 单元测试：Immediate、ByName、多 Trigger 和 DIRECT 优先级。
- Task Builder 单元测试：Args[]、Key 必填、InputMode 和异步字符串复制。
- Router 单元测试：CPU / Memory 预检查、TryEnqueue 返回处理和 Delay Queue。
- 接口集成测试：TriggerInit、EventTriggerNotify、TaskPool.TryEnqueue 和 FunctionInfo 透传。
- 地址借用集成测试：使用 SDK 保持有效的共享地址，确认本模块不复制、不释放数据；SDK 内部任务完成判定和回收不在本模块验收范围。
- 端到端测试：外部 Actor 写入 → EventTriggerNotify → Trigger / DIRECT → TaskInvocation → Pool → Function。

### 18.3 数据地址生命周期验收

1. 上游 Commit 后调用通知，数据地址与实际对象地址一致。
2. 一个事件命中多个 Task 时，所有 Task 在 Session 结束前均可读取正确数据。
3. Pool 队列延迟、协程延迟启动时，数据地址仍然有效。
4. Data SDK 保证 Delay Queue 期间地址有效，本模块不维护 Session 未完成任务计数。
5. 某个 Task 完成不能导致其他 Task 正在使用的数据被回收。
6. Session 任务完成判定和回收由 Data SDK 管控，不要求本模块提供完成回调或回收契约。
7. Scheduler / Pool 不执行 free、munmap 或 DataRef release。

### 18.4 DIRECT 与 Trigger 优先级验收

某 source_func_name 同时存在 DIRECT Dependency，且该事件的输出 Bucket 配置了 Immediate / ByName 时，本次事件只走 DIRECT。只有 source_func_name 为空或不存在 DIRECT 映射时，才走 Bucket Trigger。

## 第 19 章 验收准入与交付

### 19.1 通过标准

- TriggerInit 能读取 app.json 的全部配置，并原子发布 Registry。
- Function 以 so_name + func_name 组合标识；func_name 在 App 内唯一。
- DIRECT 只按 source_func_name / target func_name 匹配。
- Immediate / ByName 和多 Trigger 行为正确。
- DataReadyEvent 仅三个字段，EventTriggerNotify 包含独立 sourceFuncName、dataAddr、dataSize。
- TaskInvocation.Args[] 正确，Key 必须。
- 不存在 DataRef、INLINE / SHARED_MEMORY 和相关生命周期接口。
- Task Router 在 TryEnqueue 前执行 CPU / Memory 预检查。
- 资源不足、探测或计算失败不调用 TryEnqueue，记录原因后与 Pool NoCapacity 一样按 enabled 暂存重试或终止；Pool Error 不延时。
- 下游 Pool 只提供不带 ctx 的 TryEnqueue。
- 不存在 Pool 静态 Function 注册接口和未经确认的 Execution 配置。
- 所有任务数据地址在 Session 生命周期约束下有效。

### 19.2 交付物

- V0.6 完整软件设计方案。
- 第一至第六部分配套设计文档。

### 19.3 本期不作为验收目标

- Task Coroutine Pool 的队列、协程、SO Loader 和 Function 执行内部实现。
- Go Plugin、cgo 或 native SO 的技术选型。
- 资源分支的外部上报落地；本期必须验收对应日志。
- Data SDK 内部 Session 完成判定、任务计数和数据回收协议。
- Pool 实例创建、装配和生命周期管理。
- 跨进程、跨节点调度。
