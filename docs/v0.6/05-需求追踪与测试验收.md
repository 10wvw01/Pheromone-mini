## 第 17 章 功能需求与验收矩阵

### 17.1 需求追踪

| 需求组 | 核心能力 | 设计章节 | 验收范围 |
|---|---|---|---|
| APP | JSON 解析、Function 配置、索引、静态注册 | 5 | TEST-APP |
| DIR | DIRECT 独立依赖、来源函数和目标展开 | 6 | TEST-DIR |
| EVT | Immediate / ByName、多 Trigger、路径优先级 | 7 | TEST-EVT |
| TSK | input_mode、arguments[]、TaskInvocation | 8 | TEST-TSK |
| RTE | CPU / Memory 预检查、try_enqueue、Delay Queue | 9、14 | TEST-RTE |
| API | event_trigger_notify、Pool Adapter、Function ABI | 03 | TEST-API |

### 17.2 验收原则

1. 单元测试覆盖 JSON 校验、索引、DIRECT、Immediate、ByName、Task Builder 和 Task Router。
2. 参数测试覆盖 key 必填、data_addr / data_size 一致性、argc 和 argv。
3. 并发测试覆盖并发通知、共享数据地址、多目标任务、原子入队和 Delay Queue。
4. 资源测试覆盖 CPU / Memory 充足、不足和 cgroup 不可用兜底。
5. 上下游联调覆盖真实 Data SDK Commit 通知、真实 Pool try_enqueue 和 Function ABI。
6. 不再执行 DataRef 引用计数、Inline 复制、Shared-Memory retain 等已删除设计的测试。

## 第 18 章 测试与验收方案

### 18.1 测试分层

- **配置单元测试：** JSON 语法、字段类型、必填项、Function 唯一性、Bucket 唯一性和引用关系。
- **索引单元测试：** func_name 索引、DIRECT 索引、Bucket Trigger 索引。
- **Trigger 单元测试：** Immediate、ByName、多 Trigger 和 DIRECT 优先级。
- **Task Builder 单元测试：** arguments[]、key 必填、input_mode 和异步字符串复制。
- **Router 单元测试：** CPU / Memory 预检查、try_enqueue 返回处理和 Delay Queue。
- **ABI 集成测试：** dlopen、dlsym、FunctionContext 和函数参数可见性。
- **生命周期集成测试：** Session 内多 Task 并发读取，所有 Task 终态后上游回收。
- **端到端测试：** 外部 Actor 写入 → 通知 → Trigger / DIRECT → TaskInvocation → Pool → Function。

### 18.3 数据地址生命周期验收

必须验证：

1. 上游 Commit 后调用通知，数据地址与实际对象地址一致。
2. 一个事件命中多个 Task 时，所有 Task 在 Session 结束前均可读取正确数据。
3. Pool 队列延迟、协程延迟启动时，数据地址仍然有效。
4. Delay Queue 中的任务仍计入 Session 未完成任务。
5. 某个 Task 完成不能导致其他 Task 正在使用的数据被回收。
6. Session 所有相关任务完成或终止后，上游才回收数据。
7. Scheduler / Pool 不执行 free、munmap 或 DataRef release。

### 18.4 DIRECT 与 Trigger 优先级验收

必须验证：某 source_func_name 同时存在 DIRECT Dependency，且该事件的输出 Bucket 配置了 Immediate / ByName 时，本次事件只走 DIRECT。只有 source_func_name 为空或不存在 DIRECT 映射时，才走 Bucket Trigger。

## 第 19 章 验收准入与交付

### 19.1 通过标准

- JSON Parser 能解析并校验全部冻结字段。
- Function 以 so_name + func_name 组合定位；func_name 在 App 内唯一。
- DIRECT 只按 source_func_name / target func_name 匹配。
- Immediate / ByName 和多 Trigger 行为正确。
- DataReadyEvent 仅三个字段，通知参数包含独立 source_func_name、data_addr、data_size。
- TaskInvocation.arguments[] 正确，key 必须。
- 不存在 DataRef、INLINE / SHARED_MEMORY 和相关生命周期接口。
- Task Router 在 try_enqueue 前执行 CPU / Memory 预检查。
- 资源不足不调用 try_enqueue；Pool NO_CAPACITY 才进入 Delay Queue。
- Pool Adapter 只包含 try_enqueue。
- 所有任务数据地址在 Session 生命周期约束下有效。

### 19.2 交付物

- V0.6 完整软件设计方案。
- JSON 配置规范和字段解释。
- API / C ABI 文档。
- 核心模块需求清单。
- 单元测试和集成测试报告。
- 上下游接口联调记录。

### 19.3 本期不作为验收目标

- DataRef 引用计数或 DataRef Adapter。
- INLINE / SHARED_MEMORY 双载体切换。
- 资源不足的外部告警平台对接（仅 TODO）。
- Task Coroutine Pool 内部协程实现。
- 跨进程、跨节点调度。
- Rerun、执行超时和其他 Trigger Primitive。
