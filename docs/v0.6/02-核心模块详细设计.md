# 第二部分：核心模块详细设计

[返回 V0.6 主文档](../V0.6-完整软件设计方案.md)

本部分先给出核心模块总结构，再按模块展开职责、功能点、C 语言伪代码和 Mermaid 时序图。模块顺序对应运行链路：App Registry → DIRECT / Event Trigger → Task Builder → Task Router。代码片段为 C11，按需使用 stdbool.h、stddef.h、stdint.h 和 string.h。

## 第 4 章 核心模块总结构

### 4.1 模块划分

| 核心模块 | 内部功能点 | 输入 | 输出 |
|---|---|---|---|
| App Registry | JSON 解析、配置校验、全局索引、函数静态注册 | app.json | 不可变 App / Function / Bucket / Dependency / Trigger 索引 |
| DIRECT Dependency | 来源函数查询、目标函数展开、DIRECT 优先级 | DataReadyEvent.source_function | 一个或多个 DIRECT TaskAction |
| Event Trigger | Bucket 查询、Immediate、ByName、多规则匹配 | DataReadyEvent | 一个或多个 Trigger TaskAction |
| Task Builder | 输入模式转换、Inline Copy、DataRef Retain、TaskInvocation 构建 | TaskAction + DataReadyEvent | 最小 TaskInvocation |
| Task Router | 原子准入、Delay Queue、失败日志和扩展预留 | TaskInvocation | Pool 接收或 Router 持有的延时任务 |

### 4.2 模块依赖

~~~mermaid
flowchart LR
    A["App Registry"] --> B["DIRECT Dependency"]
    A --> C["Event Trigger"]
    B --> D["Task Builder"]
    C --> D
    D --> E["Task Router"]
    E --> F["Task Coroutine Pool Adapter"]
    G["Data SDK Adapter"] --> C
    G --> D
~~~

App Registry 在启动阶段构建只读索引。运行期 DIRECT Dependency 和 Event Trigger 只查询索引，不修改配置。Task Builder 不决定路由；Task Router 不重新解析 Trigger。

### 4.3 统一运行时对象

- DataReadyEvent：SDK 对成功 Commit 的最小通知。
- TaskAction：本模块内部对象，包含目标 so_name、输入模式和命中来源；不传给下游。
- TaskInvocation：交给 Pool 的最小执行描述。
- RouterPendingTask：Task Router 私有对象，包含 TaskInvocation、DataRef 所有权状态、首次入队时间和下次重试时间。

TaskAction、RouterPendingTask 都是内部结构，不构成上游或下游 ABI。

## 第 5 章 App Registry

### 5.1 功能点 APP-01：单一 app.json 注册

职责：解析并校验一份 app.json，构建所有静态索引。JSON 解析器是 App Registry 内部组件，不单独对上游开放。

配置至少包含 app_name、functions、buckets、dependencies、triggers、scheduler.delay_queue。scheduler.delay_queue 是进程级单例：第一个成功注册的 App 建立配置，后续 App 必须完全一致，否则注册失败且不发布候选 App。

C 语言伪代码：

~~~c
pm_status_t register_app(
    pm_registry_t *registry,
    const char *json_text,
    size_t json_size)
{
    pm_app_record_t *candidate = NULL;
    pm_status_t status;

    if (registry == NULL || json_text == NULL || json_size == 0U) {
        return PM_ERR_INVALID_ARGUMENT;
    }

    status = pm_parse_app_json(json_text, json_size, &candidate);
    if (status != PM_OK) {
        return status;
    }

    status = pm_validate_app(candidate, registry);
    if (status == PM_OK) {
        status = pm_validate_global_delay_config(registry, candidate);
    }
    if (status != PM_OK) {
        pm_app_record_destroy(candidate);
        return status;
    }

    status = pm_build_indexes(candidate);
    if (status != PM_OK) {
        pm_app_record_destroy(candidate);
        return status;
    }

    status = pm_register_pool_functions(registry, candidate);
    if (status != PM_OK) {
        pm_rollback_pool_functions(registry, candidate);
        pm_app_record_destroy(candidate);
        return status;
    }

    status = pm_registry_publish_atomically(registry, candidate);
    if (status != PM_OK) {
        pm_rollback_pool_functions(registry, candidate);
        pm_app_record_destroy(candidate);
        return status;
    }

    return PM_OK;
}
~~~

~~~mermaid
    participant Pool as Task Coroutine Pool
~~~

### 5.2 功能点 APP-02：Bucket 全局唯一索引

Bucket 在当前 Registry 管理的所有 App 之间全局唯一。建立 bucket_index：bucket_name → app_record + trigger_list。

C 语言伪代码：

~~~c
pm_status_t pm_validate_global_buckets(
    const pm_registry_t *registry,
    const pm_app_record_t *candidate)
{
    size_t i;

    for (i = 0U; i < candidate->bucket_count; ++i) {
        const char *name = candidate->buckets[i].name;

        if (pm_registry_bucket_exists(registry, name)) {
            return PM_ERR_DUPLICATE_BUCKET;
        }
        if (pm_candidate_bucket_duplicate(candidate, name, i)) {
            return PM_ERR_DUPLICATE_BUCKET;
        }
    }
    return PM_OK;
}
~~~

### 5.3 功能点 APP-03：Function、DIRECT 和 Trigger 引用校验

- 每个 so_name 是安全 SO 文件名，不允许路径分隔符和路径穿越。
- 每个 SO 固定导出 handler。
- so_name 在单个 App 内唯一；不同 App 若复用同一物理 so_name，必须具有一致的 resource / execution 配置，Pool 注册按 so_name 幂等。
- DIRECT 的 src_functions、tgt_functions 必须引用本 App 已注册的 so_name。
- Trigger 的 Bucket 必须在本 App 的 buckets 声明中；目标 Function 必须已注册。
- Trigger name 在 App 内唯一。
- 发现任何错误，整个 App 不发布。

C 语言伪代码：

~~~c
pm_status_t pm_validate_references(const pm_app_record_t *app)
{
    size_t i;
    size_t j;

    for (i = 0U; i < app->dependency_count; ++i) {
        const pm_dependency_t *dep = &app->dependencies[i];
        if (dep->type != PM_DEP_DIRECT ||
            dep->source_count != 1U ||
            dep->target_count == 0U) {
            return PM_ERR_INVALID_DEPENDENCY;
        }
        for (j = 0U; j < dep->source_count; ++j) {
            if (pm_app_find_function(app, dep->sources[j]) == NULL) {
                return PM_ERR_UNKNOWN_FUNCTION;
            }
        }
        for (j = 0U; j < dep->target_count; ++j) {
            if (pm_app_find_function(app, dep->targets[j]) == NULL) {
                return PM_ERR_UNKNOWN_FUNCTION;
            }
        }
    }

    return pm_validate_trigger_references(app);
}
~~~

~~~mermaid
    AR->>FI: 校验每个 so_name
~~~

## 第 6 章 DIRECT Dependency

### 6.1 功能点 DIR-01：独立依赖索引

DIRECT 配置使用 dependencies 数组，每条关系包含 type=DIRECT、src_functions 和 tgt_functions。为避免映射歧义，每条配置的 src_functions 建议只声明一个来源；一个来源可以关联多个目标。需要不同目标集合时拆成多条配置。

索引：source_so_name → ordered target_so_name[]。

DIRECT 不创建 Bucket Trigger，不参与 Immediate / ByName Primitive 匹配。

C 语言伪代码：

~~~c
pm_status_t pm_build_direct_index(
    const pm_app_record_t *app,
    pm_direct_index_t *index)
{
    size_t i;
    for (i = 0U; i < app->dependency_count; ++i) {
        const pm_dependency_t *dep = &app->dependencies[i];
        if (dep->type != PM_DEP_DIRECT ||
            dep->source_count != 1U ||
            dep->target_count == 0U) {
            return PM_ERR_INVALID_DEPENDENCY;
        }
        if (pm_direct_index_insert(
                index, dep->sources[0],
                dep->targets, dep->target_count) != PM_OK) {
            return PM_ERR_NO_MEMORY;
        }
    }
    return PM_OK;
}
~~~

~~~mermaid
sequenceDiagram
    participant AR as App Registry
    participant DI as DIRECT Index
    AR->>DI: 遍历 dependencies
    loop 每条 DIRECT 配置
        AR->>DI: insert(source_so_name, target_so_names)
        DI-->>AR: 插入结果
    end
    DI-->>AR: source_so_name → target_so_name[] 索引完成
~~~

### 6.2 功能点 DIR-02：DIRECT 优先级和目标展开

DataReadyEvent.source_function 非空时，先检查该来源函数是否有 DIRECT 目标：

- 有：生成 DIRECT TaskAction；本次事件不再执行 Bucket Trigger 匹配。
- 无：继续执行 Bucket Trigger 匹配。
- source_function 为空：直接执行 Bucket Trigger 匹配。

该优先级与 Pheromone Local Scheduler 的 direct dependency 分支一致。DIRECT 目标按配置顺序逐个生成 Task，不按目标函数去重。

C 语言伪代码：

~~~c
pm_route_path_t pm_resolve_event_path(
    const pm_registry_t *registry,
    const data_ready_event_t *event,
    pm_task_action_list_t *actions)
{
    const pm_direct_targets_t *targets;

    if (event->source_function != NULL &&
        event->source_function[0] != '\0') {
        targets = pm_find_direct_targets(
            registry, event->source_function);

        if (targets != NULL && targets->count > 0U) {
            return pm_build_direct_actions(
                targets, event, actions) == PM_OK
                ? PM_ROUTE_DIRECT
                : PM_ROUTE_ERROR;
        }
    }

    return pm_match_bucket_triggers(
        registry, event, actions) == PM_OK
        ? PM_ROUTE_BUCKET_TRIGGER
        : PM_ROUTE_ERROR;
}
~~~

时序图：

~~~mermaid

    participant SDK as Data SDK
    participant ED as Event Dispatcher
    participant DI as DIRECT Index
    participant ET as Event Trigger
    participant TB as Task Builder
    SDK->>ED: DataReadyEvent(source_function, bucket, key, session)
~~~

### 6.3 功能点 DIR-03：DIRECT 输入规则

DIRECT 将来源 Function 本次 Commit 的对象作为目标 Function 的输入，默认输入模式为 INPUT_VALUE。载体类型仍由 Data SDK 决定：

- INLINE：Task Builder 复制本次对象字节。
- SHARED_MEMORY：Task Builder 为每个目标 Task retain 一份 DataRef。
- DIRECT 不使用 trigger_option；不把 DIRECT 转换成 Immediate Trigger。

如果未来需要 DIRECT 的 Key + Value 或 Key Only 变体，应作为新的依赖配置能力单独评审，不在 V0.6 隐式推导。

C 语言伪代码：

~~~c
pm_status_t pm_build_direct_action(
    const char *target_so_name,
    const data_ready_event_t *event,
    pm_task_action_t *action)
{
    if (target_so_name == NULL || event == NULL || action == NULL) {
        return PM_ERR_INVALID_ARGUMENT;
    }

    action->so_name = pm_copy_string(target_so_name);
    action->input_mode = PM_INPUT_VALUE;
    action->event = event;
    action->route_path = PM_ROUTE_DIRECT;
    return action->so_name != NULL ? PM_OK : PM_ERR_NO_MEMORY;
}
~~~

~~~mermaid
sequenceDiagram
    participant DI as DIRECT Dependency
    participant TB as Task Builder
    participant TR as Task Router
    DI->>TB: target_so_name + DataReadyEvent
    TB->>TB: input_mode 固定 INPUT_VALUE
    TB->>TB: 按 INLINE / SHARED_MEMORY 构建输入
    TB->>TR: TaskInvocation
~~~

## 第 7 章 Event Trigger

### 7.1 功能点 EVT-01：全局 Bucket 定位

Event Trigger 根据 DataReadyEvent.bucket 查询全局 bucket_index，取得所属 App 和该 Bucket 的有序 Trigger[]。DataReadyEvent 不传 app_name。

C 语言伪代码：

~~~c
pm_status_t pm_find_bucket_triggers(
    const pm_registry_t *registry,
    const char *bucket,
    const pm_bucket_record_t **out_record)
{
    if (registry == NULL || bucket == NULL || out_record == NULL) {
        return PM_ERR_INVALID_ARGUMENT;
    }

    *out_record = pm_bucket_index_find(registry, bucket);
    return (*out_record == NULL)
        ? PM_ERR_UNKNOWN_BUCKET
        : PM_OK;
}
~~~

### 7.2 功能点 EVT-02：Immediate 匹配

Bucket 匹配成功且事件是有效 Commit 通知时，Immediate 直接命中。每条 Immediate 规则独立产生一个 TaskAction。

~~~c

{
    return rule != NULL &&
           rule->primitive_type == PM_TRIGGER_IMMEDIATE;
}
~~~

### 7.3 功能点 EVT-03：ByName 精确匹配

ByName 只执行 Key 完全相等比较，区分大小写，不支持前缀、正则、模糊匹配或跨 Session 聚合。

~~~c
bool pm_match_by_name(
    const pm_trigger_config_t *rule,
    const data_ready_event_t *event)
{
    if (rule == NULL || event == NULL ||
        rule->primitive_type != PM_TRIGGER_BY_NAME ||
        rule->key_name == NULL || event->key == NULL) {
        return false;
    }

    return strcmp(rule->key_name, event->key) == 0;
}
~~~

~~~mermaid
sequenceDiagram
    participant SDK as Data SDK
    participant ET as Event Trigger
    participant TI as Trigger Index
    participant TB as Task Builder
    SDK->>ET: DataReadyEvent(bucket, key, session)
    ET->>TI: 查询 Bucket Trigger[]
    TI-->>ET: ByName 规则
    ET->>ET: strcmp(event.key, rule.key_name)
    alt 完全相等
~~~

### 7.4 功能点 EVT-04：同 Bucket 多 Trigger 独立处理

必须遍历 Bucket 下全部规则。命中一条不停止遍历；不同 Trigger 即使目标 SO 相同，也分别生成 Task。单条规则失败不回滚其他规则已完成的任务。

~~~c
pm_status_t pm_match_all_triggers(
    const pm_bucket_record_t *bucket,
    const data_ready_event_t *event,
    pm_task_action_list_t *actions)
{
    size_t i;

    for (i = 0U; i < bucket->trigger_count; ++i) {
        const pm_trigger_config_t *rule = &bucket->triggers[i];
        bool matched = false;

        if (rule->primitive_type == PM_TRIGGER_IMMEDIATE) {
            matched = true;
        } else if (rule->primitive_type == PM_TRIGGER_BY_NAME) {
            matched = pm_match_by_name(rule, event);
        }

        if (matched) {
            pm_status_t status = pm_action_append(actions, rule, event);
            if (status != PM_OK) {
                pm_record_rule_failure(rule, status);
            }
        }
    }

    return PM_OK;
}
~~~

~~~mermaid
sequenceDiagram
    participant ET as Event Trigger
    participant TI as Bucket Trigger[]
    participant TB as Task Builder
    ET->>TI: 读取全部规则
    loop 按配置顺序逐条匹配
        TI-->>ET: 当前规则
        ET->>ET: Primitive 匹配
        alt 命中
            ET->>TB: 创建独立 TaskAction
            TB-->>ET: 构建结果
        else 未命中
            ET->>ET: 继续下一条
        end
    end
~~~

## 第 8 章 Task Builder

### 8.1 功能点 TSK-01：输入模式转换

Trigger 的 trigger_option 映射：

| trigger_option | input_mode | Task 输入 |
|---:|---|---|
| 0 | INPUT_VALUE | Value |
| 1 | INPUT_KEY_VALUE | Key + Value |
| 2 | INPUT_KEY_ONLY | Key |

DIRECT 固定为 INPUT_VALUE。Input Mode 与 Payload Type 是两个维度。

C 语言伪代码：

~~~c
pm_status_t pm_resolve_input_mode(
    bool is_direct,
    uint32_t trigger_option,
    pm_input_mode_t *out_mode)
{
    if (out_mode == NULL) {
        return PM_ERR_INVALID_ARGUMENT;
    }
    if (is_direct) {
        *out_mode = PM_INPUT_VALUE;
        return PM_OK;
    }

    switch (trigger_option) {
    case 0U:
        *out_mode = PM_INPUT_VALUE;
        return PM_OK;
    case 1U:
        *out_mode = PM_INPUT_KEY_VALUE;
        return PM_OK;
    case 2U:
        *out_mode = PM_INPUT_KEY_ONLY;
        return PM_OK;
    default:
        return PM_ERR_INVALID_TRIGGER;
    }
}
~~~

~~~mermaid
sequenceDiagram
    participant TB as Task Builder
    participant CFG as Trigger / DIRECT Config
    participant SDK as DataReadyEvent
    TB->>CFG: 读取 DIRECT 标记或 trigger_option
    alt DIRECT
        CFG-->>TB: INPUT_VALUE
    else Bucket Trigger
        CFG-->>TB: option 0 / 1 / 2
        TB->>TB: 映射为 VALUE / KEY_VALUE / KEY_ONLY
    end
    TB->>SDK: 按输入模式读取事件 Key / Payload 视图
~~~

### 8.2 功能点 TSK-02：Inline 复制和 DataRef retain

- INLINE：每个需要 Value 的 Task 独立复制字节，notify 返回后不再引用 SDK 缓冲区。
- SHARED_MEMORY：每个需要 Value 的 Task 独立 retain DataRef，不复制大数据。
- KEY_ONLY：不复制 Inline，不 retain DataRef，TaskInvocation 的 payload_type 为 NONE。
- 一个事件命中多个规则或 DIRECT 多个目标时，每个 Task 独立持有输入资源。

C 语言伪代码：

~~~c
pm_status_t pm_build_task_input(
    const pm_data_ready_event_t *event,
    pm_input_mode_t input_mode,
    pm_task_invocation_t *task)
{
    if (input_mode == PM_INPUT_KEY_ONLY) {
        task->input_mode = PM_INPUT_KEY_ONLY;
        task->key = pm_copy_string(event->key);
        task->payload_type = PM_TASK_PAYLOAD_NONE;
        task->data_size = 0U;
        return task->key != NULL ? PM_OK : PM_ERR_NO_MEMORY;
    }

    task->input_mode = input_mode;
    if (input_mode == PM_INPUT_KEY_VALUE) {
        task->key = pm_copy_string(event->key);
        if (task->key == NULL) {
            return PM_ERR_NO_MEMORY;
        }
    }

    if (event->payload_type == PM_EVENT_INLINE) {
        task->payload.inline_payload.data =
            pm_copy_bytes(event->payload.inline_payload.data,
                          event->payload.inline_payload.size);
        if (task->payload.inline_payload.data == NULL &&
            event->data_size > 0U) {
            return PM_ERR_NO_MEMORY;
        }
        task->payload.inline_payload.size = event->payload.inline_payload.size;
        task->payload_type = PM_TASK_PAYLOAD_INLINE;
    } else {
        if (pm_data_ref_validate(event->payload.shared_memory,
                                 event->data_size) != PM_OK) {
            return PM_ERR_DATA_REF;
        }
        if (pm_data_ref_retain(event->payload.shared_memory) != PM_OK) {
            return PM_ERR_DATA_REF;
        }
        task->payload.shared_memory = event->payload.shared_memory;
        task->payload_type = PM_TASK_PAYLOAD_SHARED_MEMORY;
    }

    task->data_size = event->data_size;
    return PM_OK;
}
~~~

~~~mermaid
sequenceDiagram
    participant ET as DIRECT / Event Trigger
    participant TB as Task Builder
    participant SDK as Data SDK DataRef
    participant TR as Task Router
    ET->>TB: TaskAction + DataReadyEvent
    alt INLINE 且需要 Value
        TB->>TB: 复制字节到 TaskInvocation
    else SHARED_MEMORY 且需要 Value
        TB->>SDK: validate(DataRef)
        TB->>SDK: retain(DataRef)
    else KEY_ONLY
        TB->>TB: 仅复制 Key，不持有 Payload
~~~

### 8.3 功能点 TSK-03：最小 TaskInvocation

每次任务只传递下游实际执行所需的字段：

- so_name：定位 /dev/shm/<so_name>。
- session_id：业务 Session。
- input_mode：Value / Key+Value / Key Only。
- key：仅在输入模式需要时提供。
- payload_type、data_size、Inline bytes 或 DataRef。

不传 app_name、bucket、event_id、task_id、source_function、trigger_name、source_type、resource、execution 或 entry_name。handler 固定，不逐 Task 传递。

C 语言伪代码：

~~~c
pm_status_t pm_build_task_invocation(
    const pm_app_function_t *function,
    const pm_task_action_t *action,
    const pm_data_ready_event_t *event,
    pm_task_invocation_t *task)
{
    if (function == NULL || action == NULL ||
        event == NULL || task == NULL) {
        return PM_ERR_INVALID_ARGUMENT;
    }

    memset(task, 0, sizeof(*task));
    task->so_name = pm_copy_string(function->so_name);
    task->session_id = pm_copy_string(event->session_id);
    if (task->so_name == NULL || task->session_id == NULL) {
        pm_task_invocation_clear(task);
        return PM_ERR_NO_MEMORY;
    }

    {
        pm_status_t status = pm_build_task_input(
            event, action->input_mode, task);
        if (status != PM_OK) {
            pm_task_invocation_clear(task);
            return status;
        }
    }
    return PM_OK;
}
~~~

## 第 9 章 Task Router

### 9.1 功能点 RTE-01：原子 try_enqueue

Task Router 是本地资源准入策略的拥有方，通过下游 try_enqueue 原子接口完成容量检查和入队。禁止先 query capacity 再 enqueue 的两阶段竞态设计。

C 语言伪代码：

~~~c
pm_route_result_t pm_route_task(
    pm_task_router_t *router,
    pm_pending_task_t *pending)
{
    pm_pool_submit_result_t result;

    result = router->pool.try_enqueue(
        router->pool.ctx, &pending->invocation);

    if (result == PM_POOL_ACCEPTED) {
        pm_transfer_task_ownership_to_pool(pending);
        return PM_ROUTE_ACCEPTED;
    }

    if (result == PM_POOL_NO_CAPACITY) {
        return pm_handle_no_capacity(router, pending);
    }

    pm_release_pending_task(pending);
    pm_log_pool_error(result, pending);
    return PM_ROUTE_REJECTED;
}
~~~

~~~mermaid
sequenceDiagram
    participant TB as Task Builder
    participant TR as Task Router
    participant Pool as Task Coroutine Pool
    TB->>TR: TaskInvocation

        Pool-->>TR: ACCEPTED
~~~

### 9.2 功能点 RTE-02：全局 Delay Queue

配置位于 app.json 的 scheduler.delay_queue，统一作用于全部 App 和 Function。

- enabled=false：NO_CAPACITY 时不等待，记录 PROCESS_DISPATCH_REQUIRED，释放 Task 资源。
- enabled=true：Task 和 DataRef 留在 Router Delay Queue，按 retry_interval_ms 重新调用 try_enqueue。
- 等待时间达到 max_wait_ms：记录 TASK_DELAY_EXPIRED，释放 Task 和 DataRef。
- 重试返回 ACCEPTED：Pool 接管资源，Router 删除延时项。
- 重试返回非 NO_CAPACITY 错误：终止该任务并释放资源。

C 语言伪代码：

~~~c
pm_route_result_t pm_handle_no_capacity(
    pm_task_router_t *router,
    pm_pending_task_t *pending)
{
    if (!router->delay_config.enabled) {
        pm_log_dispatch_required(pending, false);
        pm_release_pending_task(pending);
        return PM_ROUTE_NO_CAPACITY;
    }

    if (!pm_delay_queue_push(
            &router->delay_queue,
            pending,
            pm_monotonic_now_ms(),
            router->delay_config.max_wait_ms,
            router->delay_config.retry_interval_ms)) {
        pm_log_delay_queue_rejected(pending);
        pm_release_pending_task(pending);
        return PM_ROUTE_DELAY_QUEUE_REJECTED;
    }

    return PM_ROUTE_DELAYED;
}
~~~

### 9.3 功能点 RTE-03：无延时策略时的扩展预留

当 Pool 返回 NO_CAPACITY 且全局 Delay Queue 未启用时：

- 不做忙等。
- 不做真实进程间或节点间转发。
- 记录 PROCESS_DISPATCH_REQUIRED，包含内部 trace、so_name、session 和拒绝原因。
- 返回未接收状态，释放 Router 持有的 DataRef。
- 日志字段 dispatched 固定为 false。

未来可在该分支接入 Process / Node Scheduler，但不提前实现相关模块。

~~~c
pm_route_result_t pm_reject_without_delay(
    pm_task_router_t *router,
    pm_pending_task_t *pending)
{
    (void)router;

    pm_log_dispatch_required(pending, false);
    pm_release_pending_task(pending);
    return PM_ROUTE_NO_CAPACITY;
}
~~~

### 9.4 Pool 消费与协程唤醒边界

Task Router 只提交 Task，不调用单独的协程唤醒接口。Task Coroutine Pool 必须保证成功入队的 Task 最终可被其内部消费者发现；队列通知、协程等待和唤醒均由 Pool 自己实现。

C 语言伪代码：

~~~c
pm_route_result_t pm_submit_without_wakeup(
    pm_task_router_t *router,
    pm_pending_task_t *pending)
{
    pm_pool_submit_result_t result;

    result = router->pool.try_enqueue(
        router->pool.ctx, &pending->invocation);

    if (result == PM_POOL_ACCEPTED) {
        pm_transfer_task_ownership_to_pool(pending);
        return PM_ROUTE_ACCEPTED;
    }

    return pm_handle_pool_rejection(router, pending, result);
}
~~~

~~~mermaid
sequenceDiagram
    participant TR as Task Router
    participant Pool as Task Coroutine Pool
    participant Worker as Pool 内部消费者
    TR->>Pool: task_pool_try_enqueue(TaskInvocation)
    Pool->>Pool: 原子准入并写入 TaskQueue
    Pool-->>TR: ACCEPTED
    Note over TR,Pool: Router 不再调用任何唤醒 API
    Pool->>Worker: Pool 内部队列通知 / 消费调度
    Worker->>Pool: dequeue Task
~~~

Pool 内部通知机制属于下游实现细节；本模块只依赖 ACCEPTED 表示任务已经被可靠接收。
