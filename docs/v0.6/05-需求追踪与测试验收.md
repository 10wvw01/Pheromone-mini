## 第 18 章 测试与验收方案

### 18.1 测试分层

1. 单元测试：JSON 校验、索引、DIRECT、Immediate、ByName、Task Builder、Delay Queue。
2. Mock 集成测试：Mock Data SDK、Mock Task Coroutine Pool。
3. ABI 契约测试：C11 结构体、函数指针、返回码、所有权转移。
4. 并发测试：并发通知、原子入队、Delay Queue 到期处理、DataRef 引用计数。
5. 上下游联调：真实 Data SDK Commit 通知、真实 Pool try_enqueue。
6. 端到端测试：外部 Actor 写入 → Trigger / DIRECT → TaskInvocation → Pool 接收 → handler。

### 18.3 T09 / T10 数据载体验收

| 项目 | T09 小数据 | T10 大数据 |
|---|---|---|
| SDK 载体 | INLINE | SHARED_MEMORY |
| 通知内容 | inline_data + data_size | data_ref + data_size |
| 本模块 | 每个需要 Value 的 Task 复制 | validate 并为每个 Task retain |
| Router | 保留待提交副本 | 保留对应 DataRef |
| Pool 接收 | 复制 Inline 到队列任务 | 接管 DataRef |
| Pool 执行 | 提供 Value 视图 | map DataRef 并提供 Value 视图 |
| 释放 | Pool 执行结束释放副本 | Pool unmap 并 release |
| 不实现 | 消息传输和载体选择 | 共享内存分配、DataRef 创建和底层 GC |

1KB 阈值由 Data SDK 负责，边界值归属由上下游另行冻结。本模块不根据 data_size 自行转换载体。

### 18.4 DIRECT 与 Trigger 优先级验收

必须验证：某 source_function 同时存在 DIRECT Dependency，且输出 Bucket 配置了 Immediate / ByName 时，本次 DataReadyEvent 只走 DIRECT。只有 source_function 为空或不存在 DIRECT 映射时，才走 Bucket Trigger。

该规则避免同一次对象写入被 DIRECT 和 Bucket Trigger 双重触发；若未来业务需要双路广播，必须新增明确配置，不能隐式改变 V0.6 语义。

## 第 19 章 验收准入与交付

### 19.1 通过标准

- 所有 P0 单元和 Mock 集成用例通过。
- DIRECT、Immediate、ByName 和多 Trigger 语义符合设计。
- DataReadyEvent 不包含 app_name，Bucket 全局唯一约束生效。
- T09 / T10 的数据生命周期和引用计数通过。
- Pool 原子 try_enqueue 契约通过；本模块无 wake_one 调用。
- Delay Queue 开启、关闭、成功重试、超时、满载和退出清理通过。
- 所有错误终止路径没有 Inline 泄漏或 DataRef 引用泄漏。
- C11 编译告警通过；ASan / UBSan / TSan 测试通过。
- 不存在 Rerun 或 resource.timeout_ms 配置与实现。

### 19.2 交付物

1. C11 头文件与模块实现。
2. 单一 app.json 配置示例。
3. Data SDK 和 Task Coroutine Pool 接口契约。
4. 单元、Mock 集成、ABI、并发测试。
5. 测试报告、错误码和日志说明。
6. V0.6 设计文档与需求追踪矩阵。

### 19.3 本期不作为验收目标

- Node / Process Scheduler 和 Executor Warm / Cold 选择。
- Function 执行超时控制和 Rerun。
- Task Coroutine Pool 内部协程调度实现。
- Data Bucket 的共享内存池、存储和消息传输实现。
