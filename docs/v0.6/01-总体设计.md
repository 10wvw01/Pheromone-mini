## 第 1 章 功能需求列表概述

### 1.1 业务背景与本期链路

业务流程如下：

| 步骤 | 行为 | 责任方 |
|---|---|---|
| ① | SMC Actor 处理外部消息，调用 SDK 写入数据 | 上游业务团队 |
| ② | SDK 调用 Data Bucket SDK，将 Object 写入对应数据载体 | Data Bucket SDK 团队 |
| ③ | Data SDK 在 Commit 成功后发送 DataReadyEvent；本模块判断 DIRECT 或 Bucket Trigger 路径 | 上游通知 + 本模块 |
| ④ | 本模块解析依赖或匹配 Trigger，构建目标函数 TaskInvocation | 本模块 |
| ⑤ | Task Router 调用下游原子 try_enqueue；无容量时按全局 Delay Queue 策略处理 | 本模块 + 下游 Pool |
| ⑥ | Task Coroutine Pool 自行消费队列、管理协程、加载 SO 并执行 handler | 下游团队 |

本模块只负责③④⑤，不负责 SMC Actor、Object 存储、共享内存底层、Task Coroutine Pool 或业务函数执行。

| App Registry | Function 静态配置一次性注册给 Pool | P0 | 本模块 + 下游 |
| DIRECT Dependency | source_function 到一个或多个目标函数的依赖匹配 | P0 | 本模块 |
| DIRECT Dependency | DIRECT 路径优先级和独立 Task 生成 | P0 | 本模块 |
| Event Trigger | Immediate 匹配 | P0 | 本模块 |
| Event Trigger | ByName 精确 Key 匹配 | P0 | 本模块 |
| Event Trigger | 一个 Bucket 多 Trigger 独立匹配 | P0 | 本模块 |
| Task Builder | trigger_option 到输入模式映射 | P0 | 本模块 |
| Task Builder | Inline 复制、DataRef retain 和所有权管理 | P0 | 本模块 + 上游 |

### 1.3 研发边界与团队职责

**本模块负责：**

1. App Registry：解析单一 app.json，构建全局 Function、Bucket、DIRECT Dependency、Trigger 索引。
2. DIRECT Dependency：按来源 Function 查找目标 Function，独立生成任务。
3. Event Trigger：按 Bucket 找到规则，匹配 Immediate / ByName。
4. Task Builder：构造最小 TaskInvocation，管理 Inline 和 DataRef 生命周期。
5. Task Router：调用原子 try_enqueue，管理本地 Delay Queue 和拒绝日志。

**上游 Data Bucket SDK 负责：**

- Object 创建、容量校验、写入和 Commit。
- 小数据消息传递、大数据共享内存存储及 1KB 阈值选择。
- DataReadyEvent 通知。
- DataRef 创建、validate、retain、release。
- Function handler 通过 Object API 写对象时，注入 source_function；外部 SMC Actor 写入时可不提供 source_function。

**下游 Task Coroutine Pool 负责：**

- 接收函数静态配置并维护可执行函数元数据。
- 原子检查可接收位置并入队。
- 队列消费、协程创建/等待/唤醒。
- SO 加载、handler 符号解析、输入视图准备和执行。
- 执行完成后释放其持有的 Inline / DataRef 资源。

### 1.4 冻结的基础约束

| 约束 | 设计要求 |
|---|---|
| 配置 | 仅 app.json；注册入口为 register_app |
| App | app_name 是 App Registry 全局唯一 KEY |
| Bucket | 所有已注册 App 之间全局唯一；DataReadyEvent 不传 app_name |
| SO | 每个 SO 固定放置于 /dev/shm；SO 名称是安全文件名 |
| Function | 无状态；每个 SO 固定导出 handler |
| DIRECT | 独立依赖路径；不作为 Trigger Primitive |
| Trigger | 仅 Immediate、ByName |
| 多 Trigger | 一个 Bucket 可以关联多个 Trigger |
| 数据 | APP 只能使用 Object/Data SDK，不得直接用文件 I/O 或网络 Socket 交换业务数据 |
| Payload | SDK 负责约 1KB 阈值和载体选择；本模块不重复判断 |
| 共享内存 | 已提交对象不可变；覆盖写不自动产生通知；DataRef 必须绑定本次 Commit 版本 |
| 入队 | try_enqueue 原子完成容量判断和入队 |
| 协程 | Pool 内部管理消费和唤醒；本模块不调用 wake_one |
| 延时 | app.json 全局配置 Delay Queue |
| 超时 | 不定义 Function 执行超时，不实现 Rerun |

全局 Delay Queue 语义：scheduler.delay_queue 是进程级单例配置。第一次成功 register_app 建立该配置；后续 App 注册必须声明完全相同的 enabled、retry_interval_ms、max_wait_ms，否则注册失败。该配置统一作用于当前 Registry 的全部 App、Function 和 Trigger。

### 1.5 本期明确不实现

- Rerun、Function 执行超时、resource.timeout_ms。
- wake_one 或由本模块发起的协程唤醒。
- BySet、ByBatchSize、ByTime、DynamicGroup、Redundant 等其他 Trigger Primitive。
- Node / Process Scheduler、Warm / Cold Executor、跨进程和跨节点任务分发。
- Data Bucket 底层存储、共享内存池、消息传输和阈值选择。
- Task Coroutine Pool、TaskQueue、协程和 SO 执行实现。
- 动态 Trigger 更新、持久化事件日志、Exactly-once 和事件去重。
- APP 文件 I/O、网络 Socket 沙箱拦截；本期通过 API 契约和代码审查落实禁用约束。

### 1.6 术语

| 术语 | 含义 |
|---|---|
| App | 由一份 app.json 描述的应用配置集合 |
| app_name | App Registry 的注册 KEY |
| so_name | SO 文件名，也是 Function 的执行标识 |
| DIRECT Dependency | 来源 Function 到目标 Function 的独立依赖关系 |
| Bucket | 全局唯一的数据逻辑命名空间 |
| DataReadyEvent | Data SDK 对一次成功 Commit 发出的通知 |
| DataRef | 指向已提交共享内存对象版本的不透明引用 |
| Immediate | Bucket 收到有效数据事件时命中 |
| ByName | Bucket 命中且 Key 完全相等时命中 |
| TaskInvocation | 提交给 Task Coroutine Pool 的最小一次函数调用描述 |
| Delay Queue | 本地资源不足时暂存待提交任务的延时队列 |

## 第 2 章 Pheromone 源码参考与裁剪

V0.6 继承 Pheromone 的 DIRECT 优先路径、Bucket → Trigger 列表以及 Immediate / ByName 的匹配语义。单进程场景不需要 Coordinator、跨节点数据位置同步或冷热 Executor 分发。原项目的分布式消息字段不直接复制到本模块接口。

源码定位、继承与裁剪边界见 [附录 A](appendix/A-Pheromone源码映射.md)。

## 第 3 章 总体软件架构

### 3.1 核心模块架构

~~~mermaid
flowchart TD
    A["app.json"] --> B["App Registry"]
    B --> C["Function Index"]
    B --> D["Global Bucket Index"]
    B --> E["DIRECT Dependency Index"]
    D --> F["Bucket -> Trigger[]"]
    G["DataReadyEvent"] --> H["Event Dispatcher"]
    H --> I{"source_function 有 DIRECT 依赖？"}
    E --> I
    I -->|是| J["DIRECT Dependency"]
    I -->|否| K["Event Trigger"]
    F --> K
    J --> L["Task Builder"]
    K --> L
    L --> M["Task Router"]
    M --> N["原子 task_pool_try_enqueue"]
    N --> O["Task Coroutine Pool"]
    M --> P["全局 Delay Queue"]
    P --> M
~~~

### 3.2 关键控制流与数据流

**注册控制流：**

1. 上游将完整 app.json 内容传入 register_app。
2. App Registry 校验 app_name、so_name、Bucket、DIRECT 和 Trigger 引用。
3. 检查 Bucket 在当前 Registry 全局唯一。
4. 构建 Function、Bucket、DIRECT、Trigger 索引。
5. 将 Function 静态 resource / execution 配置一次性注册给 Task Coroutine Pool。
6. 全部成功后原子发布 AppRecord 和索引；失败时回滚临时索引及已完成的下游注册。

**运行时数据流：**

1. Data SDK 完成 Object Commit 后构造 DataReadyEvent。
2. Event Dispatcher 根据 Bucket 全局索引定位所属 App。
3. 如果 source_function 存在 DIRECT 依赖，生成 DIRECT Task；本次事件不再执行 Bucket Trigger 匹配。
4. 如果不存在 DIRECT 依赖，按 Bucket 获取 Trigger[] 并逐条匹配。
5. Task Builder 为每个命中目标生成独立 TaskInvocation。
6. Task Router 调用原子 try_enqueue；NO_CAPACITY 时根据全局 Delay Queue 配置处理。
7. Pool 自行消费队列并管理协程。

### 3.3 架构原则

- **配置与事件分离：** app.json 描述静态依赖和触发规则；DataReadyEvent 只描述一次数据提交。
- **Bucket 全局寻址：** Bucket → App → Trigger[]，DataReadyEvent 不携带 app_name。
- **DIRECT 与 Trigger 分离：** DIRECT 是依赖路径；Immediate / ByName 是 Bucket Trigger Primitive。
- **执行信息最小化：** TaskInvocation 只携带下游实际执行所需信息；Trigger 和路由元数据留在本模块。
- **所有权显式：** Inline 复制；DataRef retain；Pool 接收后接管。
- **本地边界明确：** Task Router 不创建或唤醒协程，不实现远程分发。
- **失败可解释：** 容量不足、延时等待、超时、非法配置和 DataRef 错误分别记录，不混为队列满。
