# Pheromone-mini V0.5 完整软件设计方案

**版本：** V0.5  
**日期：** 2026-11-25  
**状态：** 预研 Demo 设计基线  
**实现语言：** C11

## 1. V0.5 核心结论

V0.5 是面向当前预研 Demo 的最小调度与 Trigger 设计。只负责业务流程③④⑤：接收 DataReadyEvent、匹配 Trigger、构建 TaskDescriptor，并提交给下游 Task Coroutine Pool。

| 维度 | V0.5 冻结基线 |
|---|---|
| 调度范围 | 单节点、单进程内；本模块只做本地 Task Router |
| 本地任务队列 | 下游 Task Coroutine Pool 拥有和实现 |
| 队列满 | 只打印 PROCESS_DISPATCH_REQUIRED，返回未接收；不实际跨进程分发 |
| Trigger | 仅 Immediate、ByName |
| DIRECT Dependency | 本期完全不实现，不保留独立路径或兼容分支 |
| 配置入口 | 上游将一份完整 app.json 传给 register_app(config_json) |
| App Registry | 本模块负责；内部完成 JSON 解析、校验、Function Index、Trigger Index 构建 |
| Function / Trigger Registry | App Registry 内部索引，不单独向上游开放注册 API |
| Bucket | 一个 Bucket 可以关联多个 Trigger；每条命中规则独立生成 Task |
| 函数 | 无状态；每个 SO 固定导出 handler |
| SO 部署 | 每个节点固定放在 /dev/shm；下游框架自动加载 /dev/shm/<so_name> |
| 数据载体 | INLINE 或 SHARED_MEMORY，由 Data Bucket SDK 选择并显式标记 |
| T09 / T10 | 验证小数据 Inline 和大数据 DataRef 的接入、组装、生命周期及下游传递；不实现底层传输 |
| Object 约束 | APP 只能通过 Object/Data SDK 交换数据；不得直接使用文件 I/O、网络 Socket |
| 覆盖写 | 同 Bucket/Key 覆盖但无新通知，不触发新 Task；已持有 DataRef 必须保持原版本稳定 |

## 2. 研发边界

### 2.1 本模块负责

1. **App Registry**：唯一注册入口 register_app；管理 app_name、函数元信息、Bucket 和 Trigger。
2. **Event Trigger**：接收 SDK 数据就绪通知，匹配 Immediate / ByName。
3. **Task Builder**：组装完整 TaskDescriptor，Inline 数据复制，Shared-Memory DataRef retain 并传递。
4. **Task Router**：调用下游 try_enqueue，成功后 wake_one；队列满只记录日志并返回未接收。

### 2.2 上游 Data Bucket SDK 负责

Object 创建与容量校验、数据写入和 Commit、共享内存管理、消息传输、1KB 阈值策略、Payload 类型选择、DataRef 创建及底层生命周期保护。SDK 在数据成功提交后调用 event_trigger_notify。

### 2.3 下游 Task Coroutine Pool 负责

TaskQueue、协程创建/等待/唤醒、SO 加载、handler 符号解析、Inline/DataRef 输入视图准备、handler 执行、执行状态和最终资源释放。

### 2.4 明确不做

不实现 DIRECT Dependency、其他 Trigger Primitive、Node/Process Scheduler、跨进程分发、共享内存池、Object 存储、1KB 阈值判断、Payload 转换、Task Coroutine Pool、动态 Trigger 更新、自动重试、Exactly-once 和 P0 去重。

## 3. 总体架构

~~~mermaid
flowchart TD
    A["SMC Actor"] --> B["SDK / Data Bucket SDK"]
    B --> C["Object 写入 / Commit"]
    C --> D["DataReadyEvent：INLINE 或 SHARED_MEMORY"]
    subgraph M["本模块：单节点 / 单进程"]
      AR["App Registry<br/>register_app(app.json)<br/>Function Index / Trigger Index"]
      ET["Event Trigger<br/>Immediate / ByName"]
      TB["Task Builder<br/>Inline Copy / DataRef Retain"]
      TR["Task Router"]
      AR -.只读索引.-> ET
      AR -.函数元信息.-> TB
      D --> ET --> TB --> TR
    end
    TR -->|"try_enqueue"| P["下游 Task Coroutine Pool / TaskQueue"]
    TR -->|"QUEUE_FULL：仅日志"| L["PROCESS_DISPATCH_REQUIRED<br/>dispatched=false"]
    P -->|"wake_one"| W["工作协程"]
    W --> H["/dev/shm/<so_name> / handler"]
~~~

### 3.1 注册链路

上游将完整 app.json 内容传给 register_app。App Registry 在一次注册事务内解析和校验 JSON，建立 Function Index 和 Bucket→Trigger Index，以 app_name 为全局唯一 KEY 原子发布。配置只注册一次，运行期只读。

### 3.2 数据触发链路

Data SDK 在 Object Commit 成功后构造 DataReadyEvent。Event Trigger 依据 app_name、Bucket 找到规则，逐条执行 Immediate/ByName 匹配。每条命中规则交给 Task Builder；未命中是正常结果。

### 3.3 Task 输入链路

- INLINE：事件携带小数据；Task Builder 在 notify 返回前复制到 TaskDescriptor，之后不再依赖 SDK 的临时缓冲区。
- SHARED_MEMORY：事件携带 DataRef；Task Builder 为每个需要 value 的 Task retain 一份引用，不复制实际 Payload。
- KEY_ONLY：只传递 Key，不复制 Payload、不 retain DataRef。

### 3.4 本地调度链路

Task Router 调用下游 try_enqueue。入队成功后调用 wake_one；没有等待协程不影响入队结果。队列满时只记录 PROCESS_DISPATCH_REQUIRED 并返回未接收，不做进程间分发。

## 5. 对外关键接口

~~~c
int app_registry_create(app_registry_t **out,
                        const scheduler_adapters_t *adapters);

int register_app(app_registry_t *registry,
                 const char *config_json,
                 size_t config_size);

int app_registry_seal(app_registry_t *registry);

int event_trigger_notify(app_registry_t *registry,
                         const data_ready_event_t *event,
                         trigger_result_t *result);

void app_registry_destroy(app_registry_t *registry);
~~~

register_app 是唯一的配置注册入口；event_trigger_notify 是 Data SDK 的运行时数据通知入口。Function Index、Trigger Index、Task Builder 和 Task Router 均不作为上游独立注册 API。

## 6. T09 / T10 验收边界

| 用例 | T09：小数据 | T10：大数据 |
|---|---|---|
| SDK 载体 | INLINE | SHARED_MEMORY |
| 事件携带 | inline_data + data_size | data_ref + data_size |
| Task Builder | 复制字节 | retain 并原样传 DataRef |
| Task Pool | 使用任务描述符中的字节副本 | map DataRef，执行完成后 release |
| 本模块不实现 | 消息传输、阈值判断、载体转换 | 共享内存分配、DataRef 创建、大数据复制 |
| 核心验收 | 原事件缓冲区释放后 Task 仍可读 | DataRef 指向正确版本，引用计数平衡 |

1KB 的精确边界和边界值归属由 Data Bucket SDK 团队冻结。本模块不重新判断 data_size。

## 7. 重要接口阻塞项

1. Data SDK 必须确认 DataRef 如何绑定一次 Commit 的不可变版本，尤其同 Bucket/Key 覆盖写时如何保证已 retain 的旧引用稳定。
2. Data SDK 必须确认 Inline 缓冲区至少在 notify 返回前有效。
3. Task Pool 必须确认 try_enqueue 的原子接收、描述符复制和引用接管语义。
4. Task Pool 必须确认 wake_one 无等待者时的返回语义，以及队列内部如何避免丢唤醒。
5. 上下游必须共同冻结 handler ABI、Object API 和 /dev/shm/<so_name> 加载约定。
