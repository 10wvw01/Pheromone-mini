## 第 20 章 测试与验收方案

### 20.1 测试分层和环境

Linux C11，使用 Mock SDK/Pool 先验证本模块的确定性；对真实 SDK/Pool 执行契约测试和端到端联调。Mock Pool 是测试替身，不代表生产实现。每项记录配置、事件输入、预期/实际 Task 数量、逐项状态、引用计数和日志。编译工具、硬件和实测数据随报告记录。

### 20.2 配置与 Registry 测试

| 用例 | 输入/操作 | 预期 |
|---|---|---|
| T01 | docs/examples/app.json，不传函数文件 | 正常加载，应用字段与基础资源完整 |
| T02 | 加载匹配 name 的 function.json；另测无文件、多个不同函数文件 | 正常合并；不改变拓扑 |
| T03 | CPU=1.5、GPU、disk/network、execution 全字段 | 描述符字段及单位一致；不承诺强制策略 |
| T04 | 非法 JSON、重复字段、未知字段、超长、整数溢出、非整数内存值 | 启动失败，临时数据全部清理 |
| T05 | 未知目标、未知 Bucket、未知 Primitive、非法 trigger_option、非 DIRECT | 启动失败 |
| T06 | 同名多个补充文件、未知 name、depends_on 不一致、conditions 非空 | 启动失败；无隐式注册 |

### 20.4 Task Builder、Router 与协作接口

| 用例 | 输入/操作 | 预期 |
|---|---|---|
| T27 | 带完整静态资源及动态身份的 Action | descriptor 与配置/事件一致，栈对象退出后池副本仍有效 |
| T28 | 一个事件匹配 N 项 | 每项独立 retain；完成/拒绝后逐份 release |
| T29 | 注入 retain 失败 | 对应 item 构建失败，无入队、无额外引用 |
| T30 | 队列剩余一槽，多线程并发 try_submit | 最多一个成功，无超卖 |
| T31 | 有等待协程 / 无等待协程且队列有空位 | 均接收，尝试唤醒；无人等待时任务保留 |
| T32 | 队列满 | ROUTE_PROCESS_REQUIRED、未入队、日志 dispatched=false、释放引用、无真实分发 |
| T33 | Pool not ready / resource unavailable / invalid / internal error | 对应 route 失败，未入队、释放引用，不误报满队列 |
| T34 | Pool 接收后立即执行或延迟执行/取消 | 仅 Pool release 一次，描述符独立保存；拒绝只由 Router release |
| T35 | init 失败、notify 合法/非法、destroy 前停止并等在途 | 接口契约正确，无悬空句柄 |
| T36 | 同 Key 新版本写入，旧版本仍被 Task 持有 | 旧引用仍读取旧对象，release 后才允许回收 |
| T37 | 真实池高并发提交、空闲到睡眠竞态 | 无丢唤醒、无重复入队、返回值无歧义 |
| T38 | 真实部署 producer.so、processor.so / 缺失符号或文件 | 正常执行 handler；加载失败由 Pool 报告并释放引用 |
| T39 | DIRECT 两目标，第一接受第二满队列；多规则同类场景 | matched=2/enqueued=1/overflow=1/failed=0；不回滚不盲重放 |
| T40 | 关闭 engine 时池仍有已接受 Task | 停止新 notify 并排空在途；池副本有效，SDK 存活到清理 |
| T41 | 对成功、未命中、错误和满队列查日志 | ID 贯通，满队列日志不是实际分发；不写 Payload |
| T42 | 固定容量、并发、数据大小、规则数量，预热后压测 | 按第 16 章记录样本和 p50/p95/p99；区分提交与执行 |

### 20.5 异常、并发与稳定性

对失败分支注入内存分配失败、无效 DataRef、池拒绝、配置解析失败；使用 ASan/UBSan 检查泄漏/UAF，独立 TSan 压测并发。Mock 引用计数：测试结束所有基础引用和 Task 引用都释放，余额为 0；接受数与池实际入队数一致。真实 Pool 的取消/错误清理通过契约测试验证，而非本模块自行模拟生产执行器。

### 20.6 端到端 Demo 验收

使用 docs/examples 的两份配置。外部 Actor 写 b_input，value 为 uint32_t → Immediate producer.so → producer 输出 direct_invoc → DIRECT processor.so；另向 b_named 写 key=input，ByName 触发 processor.so，非匹配 key 不触发。验证 session、输入值、SO 路径、handler 入口以及 DataRef 引用余额。另在池满时验证日志及返回状态，无实际跨进程投递。

准入条件：全部 P0 本模块测试、两侧接口契约测试、三个触发路径的真实单进程集成通过；无数据引用泄漏；性能基线可复现。若真实 SDK/Pool 未提供，允许先完成 Mock 阶段，但不得标记正式联调验收通过。
