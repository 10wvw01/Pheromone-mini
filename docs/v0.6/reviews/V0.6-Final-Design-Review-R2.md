## 2. 最新约束核对

| 检查项 | 结论 |
|---|---|
| 语言与 API | Go；上游 PM-API-001 TriggerInit、PM-API-002 EventTriggerNotify，下游 POOL-API-001 TryEnqueue；无 ctx、静态注册或 wake_one |
| 配置 | 用户自行编写唯一 app.json，Function 内嵌 functions[]；路径输入，模块读取解析校验；附录与文件示例相同 |
| 初始化 | 全部预期 App 串行初始化成功后才通知；未就绪拒绝；首个合法通知进入 Running，之后不接收新配置 |
| 数据与任务 | 事件仅 Bucket / Key / SessionID；来源、地址和长度独立传入；Args 长度 1、Key 必须，FunctionInfo 随任务传递，无 DataRef / Execution |
| 职责边界 | SDK 管地址有效性、Session 完成判定与回收；下游 / 集成方管 Pool 装配；本模块不新增这两类协议 |
| 触发 | DIRECT 独立优先，多目标独立；无 DIRECT 才走 Immediate / ByName；多规则分别触发，不加事件去重 |
| 资源 | 首次及每次重试必查 CPU / Memory，采样、单位、限额、快照及异常规则明确；不承诺资源预留 |
| 延时 | 资源不足、探测失败、计算失败、Pool NoCapacity 共用 enabled；开启暂存、关闭日志并终止；Error 不延时；首次 deadline 固定，原因变化不重置，提交前再次查超时 |
| 异步与内存 | 复制描述符，不复制或释放数据；Accepted 后不再提交同一任务；拒绝不接管；数据由 SDK / 测试夹具保持有效 |
| 验收 | A 独立、B Mock E2E、C 真实联调分列；Mock 引用相同生产类型并运行真实调度，包含异步输出回流、最终结果断言、故障、并发和 Linux 验证 |
| 结论真实性 | 设计覆盖、静态检查、示例编译、功能验收不混写；Mock 不证明真实 SDK 回收、Pool 原子性 / 唤醒 / SO Loader |

## 4. 本轮发现及修正

| 编号 | 发现 | 修正及复核 |
|---|---|---|
| R2-01 | 正整数仍可能在毫秒转 Duration / 内存转字节时溢出；多 App 全局配置冲突缺少直接用例 | 附录 B 补无损整数解析、Go 数值类型范围、毫秒上限 9223372036854、memory_mb 上限 17592186044415；初始化拒绝超界及全局延时配置冲突，保留已发布状态。新增 TEST-APP-15–16，各处检查数更新为 81；已关闭 |
| R2-02 | Mock 必须有输出的文字未排除拒绝、Error、退出等负向场景 | 附录 E 明确这些场景按预期无最终输出，但必须检查终止原因、状态及次数；已关闭 |
| R2-03 | TryEnqueue 非阻塞性、NoCapacity 重试间隔及“deadline 后重试”表述不够明确 | 接口明确不等待容量或执行完成、不在调用栈同步执行业务；NoCapacity 同样按间隔且不重置 deadline；修正时序文字，区分首次无 deadline；已关闭 |
| R2-04 | 两个历史报告锚点失效，上游链接跟随 main，Go 示例未格式化 | 修复锚点、固定上游提交、五份示例经 gofmt；保存 R1 历史报告并新建 R2；已关闭 |

复核无剩余 P1 / P2 设计阻塞项。未增加第三个业务 API，未扩大 Session、Pool 装配、跨进程或节点调度范围。
